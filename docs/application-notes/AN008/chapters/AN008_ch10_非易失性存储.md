# 第10章 非易失性存储

> PMBus 设备通过 Store/Restore 命令族实现运行参数的持久化保存与恢复。本章讲解非易失性存储（Non-Volatile Memory, NVM）的三层参数模型、上电加载机制、各 Store/Restore 命令的语义差异，以及写入次数限制等工程约束。理解这些内容是正确使用 `ON_OFF_CONFIG` / `OPERATION` 控制电源上电行为的基础（详见第 9 章），也是开发 Host Driver 时配置 NVM 策略的前提。

---

## 10.1 三层参数模型

PMBus 设备内部通常维护三个层次的参数存储区域：

| 层级 | 存储介质 | 作用 | 掉电保持 |
|------|----------|------|----------|
| Factory Default（出厂默认配置） | NVM | 生产校准时写入的基线参数 | 是 |
| User Store（用户配置区） | NVM | 用户通过 `STORE_USER_ALL` 保存的配置 | 是 |
| Operating Memory（运行内存） | RAM | 当前实际生效的运行参数 | 否 |

各层级的定位：

- **Factory Default**：出厂基线，包含校准系数、默认输出电压、保护阈值等，通常不允许用户修改。
- **User Store**：系统级定制参数的持久化区域，如客户特定的电压微调、启动延时等。
- **Operating Memory**：Host 通过 PMBus 写命令直接修改的运行参数区，掉电后丢失，除非事先执行 Store 操作将其保存到 User Store。

> **提示**：并非所有 PMBus 设备都实现完整的三层结构。部分设备只有单存储区模型（详见 10.2 节）。使用前应查阅具体产品 Datasheet 确认存储架构。

## 10.2 存储架构变体

不同产品的 NVM 实现存在差异。以下是三种常见模型：

### 10.2.1 双存储区模型（推荐）

设备内部同时保留 Factory Default 和 User Store 两套独立的 NVM 区域：

```text
Factory Default (NVM, protected)
        ↕ RESTORE_DEFAULT_ALL
User Store (NVM, writable)
        ↕ STORE_USER_ALL / RESTORE_USER_ALL
Operating Memory (RAM)
```

此模型支持真正的"恢复出厂设置"：`RESTORE_DEFAULT_ALL` 可以从不可被用户覆盖的 Factory Default 重新加载参数。

### 10.2.2 单存储区模型

设备只有一套可改写的持久化配置区：

```text
Single NVM Store (writable)
        ↕ STORE / RESTORE
Operating Memory (RAM)
```

此模型下：
- Store 操作会将当前运行值覆盖唯一的 NVM 区。
- `RESTORE_DEFAULT_ALL` 恢复的是"最近一次保存的值"，而非出厂值。
- 不支持真正意义上的恢复出厂设置。

### 10.2.3 无用户可写 NVM

设备不暴露任何 Store 命令，所有参数在掉电后恢复为固定默认值。部分服务器模块电源采用此策略。

| 产品类型 | 典型存储架构 | Store 支持 |
|----------|-------------|------------|
| 数字 POL 控制器 | 双存储区 | `STORE_USER_ALL` + `RESTORE_DEFAULT_ALL` |
| 板级电源 IC | 双存储区或单存储区 | 通常允许 Store |
| 服务器模块电源 | 无用户可写 NVM | Store 命令通常禁用 |

## 10.3 上电自动恢复机制

设备上电时，参数加载遵循固定顺序：

```text
Power On
  → 1. 加载 Factory Default 到 Operating Memory
  → 2. 检查 User Store 是否有效（valid flag / checksum）
  → 3. 若有效，用 User Store 覆盖 Operating Memory
  → 4. Operating Memory 即为当前运行参数
```

关键行为说明：

- **User Store 优先级高于 Factory Default**：如果 User Store 中有有效数据，上电后会覆盖 Factory Default 的对应参数。
- **User Store 无效时回退**：如果 User Store 的校验和（checksum）不通过或 valid flag 未置位，设备将从 Factory Default 启动。
- **RAM 参数临时不保存**：Host 在运行期间通过 PMBus 写命令修改的参数仅驻留在 Operating Memory 中，掉电即丢失，除非执行 `STORE_USER_ALL`。

> **提示**：部分设备的 `RESTORE_DEFAULT_ALL` 不仅将 Factory Default 加载到 Operating Memory，还会同步覆盖 User Store。这样设计是为了确保恢复出厂设置后，下次上电不会从旧的用户配置启动。具体行为需参见产品 Datasheet。

## 10.4 Store/Restore 命令详解

PMBus 规范定义了以下四个 NVM 操作命令：

| 命令 | 命令码 | 数据方向 | 说明 |
|------|--------|----------|------|
| `STORE_DEFAULT_ALL` | `0x15` | 写入 | 将 Operating Memory 保存到 Default Store |
| `RESTORE_DEFAULT_ALL` | `0x16` | 写入 | 将 Default Store 加载到 Operating Memory |
| `STORE_USER_ALL` | `0x17` | 写入 | 将 Operating Memory 保存到 User Store |
| `RESTORE_USER_ALL` | `0x18` | 写入 | 将 User Store 加载到 Operating Memory |

### 10.4.1 STORE_USER_ALL

将 Operating Memory 中的参数复制到 User Store：

```text
Operating Memory (RAM)
        ↓ 写入
User Store (NVM)
```

典型使用流程：

1. Host 通过 PMBus 写命令修改运行参数（如 `VOUT_COMMAND`、`IOUT_OC_FAULT_LIMIT` 等）。
2. 确认参数生效后，发送 `STORE_USER_ALL (0x17)`。
3. 设备将支持持久化的参数写入 User Store。
4. 下次上电时，这些参数将自动加载。

> **提示**：不是所有 PMBus 可写命令都支持持久化。具体哪些参数可以进入 User Store，参见产品 Datasheet 中的参数白名单。编程示例详见第 16 章。

### 10.4.2 RESTORE_USER_ALL

将 User Store 中的参数复制回 Operating Memory：

```text
User Store (NVM)
        ↓ 加载
Operating Memory (RAM)
```

使用场景：在运行期间放弃当前调试修改，回到上次保存的用户配置。

### 10.4.3 RESTORE_DEFAULT_ALL

将 Default Store（通常是 Factory Default）加载到 Operating Memory：

```text
Factory Default (NVM)
        ↓ 加载
Operating Memory (RAM)
```

使用场景：恢复出厂配置，用于系统维护、故障排查或参数重置。

> **提示**：在双存储区模型中，`RESTORE_DEFAULT_ALL` 恢复的是出厂基线。但在单存储区模型中，它恢复的可能是最近一次 Store 操作写入的值。使用前务必确认设备的存储架构（参见 10.2 节）。

### 10.4.4 STORE_DEFAULT_ALL（通常被禁用）

将 Operating Memory 保存到 Default Store：

```text
Operating Memory (RAM)
        ↓ 写入
Default Store (NVM)
```

> **警告**：在大多数模块电源产品中，`STORE_DEFAULT_ALL` 被禁用或受到严格限制。

禁用原因：

| 原因 | 说明 |
|------|------|
| 防止误修改关键参数 | 避免用户将错误的 OVP/UVP/OCP 阈值永久写入出厂基线 |
| 保证模块一致性 | 服务器系统中大量并联模块需保持参数一致 |
| 简化运维管理 | 固定参数便于故障排查和 RMA 分析 |
| 生产流程控制 | 出厂校准完成后 NVM 写保护被锁定 |

如果设备允许 Store 操作，通常会附加保护机制：

- **密码保护**：必须先通过 `MFR_PASSWORD` 验证。
- **专用解锁命令**：如厂商特定命令 `MFR_UNLOCK`。
- **硬件使能**：需要外部引脚（如 `WRITE_ENABLE` pin）配合。

| 产品类型 | `STORE_DEFAULT_ALL` | `STORE_USER_ALL` | `RESTORE_DEFAULT_ALL` |
|----------|---------------------|------------------|----------------------|
| 数字 POL 控制器 | 通常允许 | 允许 | 允许 |
| 服务器模块电源 | 通常禁止 | 通常禁止 | 允许 |

## 10.5 RESTORE_DEFAULT_ALL 与 RESTORE_USER_ALL 的区别

这两个命令恢复的参数来源不同，理解其差异是正确使用 NVM 功能的关键。

| 对比项 | `RESTORE_DEFAULT_ALL` | `RESTORE_USER_ALL` |
|--------|----------------------|--------------------|
| 恢复来源 | Factory Default | User Store |
| 恢复结果 | 出厂基线参数 | 用户上次保存的参数 |
| 对 User Store 的影响 | 可能覆盖（取决于实现） | 无影响 |
| 使用场景 | 恢复出厂设置、系统维护 | 放弃临时修改、回到用户配置 |

### 参数变化示例

假设出厂默认输出电压为 1.0 V，用户修改为 1.2 V 并执行 `STORE_USER_ALL`：

| 操作前 | Factory Default | User Store | Operating Memory |
|--------|----------------|------------|-----------------|
| — | 1.0 V | — | 1.0 V |
| 修改 + `STORE_USER_ALL` | 1.0 V | 1.2 V | 1.2 V |
| 执行 `RESTORE_DEFAULT_ALL` | 1.0 V | 1.2 V（或被覆盖为 1.0 V） | 1.0 V |
| 执行 `RESTORE_USER_ALL` | 1.0 V | 1.2 V | 1.2 V |

> **提示**：`STORE_USER_ALL` 不会改变 Factory Default。两套 NVM 区域始终独立。

## 10.6 写入次数限制与安全策略

NVM（如 EEPROM 或 Flash）具有物理写入寿命限制，这是工程设计中必须考虑的约束。

### 10.6.1 常见工程约束

| 约束项 | 说明 |
|--------|------|
| 写入寿命 | NVM 有最大擦写次数限制（典型值：100K ~ 1M 次），不应允许 Host 高频写入 |
| 写入耗时 | Store 操作可能需要毫秒级甚至更长时间完成，期间设备可能 NACK 或报告 busy |
| 掉电保护 | 写入过程中掉电可能导致 User Store 数据损坏，需依赖 valid flag 或 checksum 机制 |
| 参数白名单 | 并非所有 PMBus 可写命令都应进入 NVM，设备通常只持久化特定的用户可配置参数 |
| 写保护 | 生产参数和安全参数应在硬件或固件层面受保护 |

### 10.6.2 Store 操作期间的行为

Store 命令的执行需要时间。在此期间，设备可能采取以下行为之一：

- **NACK 总线请求**：在 Store 完成前，对后续 PMBus 命令返回 NACK。
- **报告 busy 状态**：通过 `STATUS_BYTE` 或 `STATUS_WORD` 报告设备忙。

> **提示**：Store 操作耗时参数（如 `Tstore`）参见具体产品 Datasheet。Store 执行期间移除输入功率可能导致 User Store 数据损坏。

### 10.6.3 推荐的 Store 策略

1. **集中写入**：在所有参数调整完成后，仅执行一次 `STORE_USER_ALL`，而非每修改一个参数就 Store 一次。
2. **上电后延迟 Store**：避免在上电初始化阶段立即执行 Store 操作。
3. **确认写入完成**：Store 命令发送后，等待设备 ACK 确认写入完成，再进行后续操作。
4. **系统设计时预留恢复手段**：确保系统可以通过 `RESTORE_DEFAULT_ALL` 回到安全状态。

## 10.7 NVM 操作注意事项

在实际系统开发中，Host 端操作 NVM 时需注意以下事项：

### 10.7.1 确认设备存储架构

在编写 Host Driver 之前，应先通过以下步骤确认设备的 NVM 实现：

1. 查阅产品 Datasheet 的命令支持列表（Command Support Matrix），确认支持哪些 Store/Restore 命令。
2. 尝试发送 `STORE_USER_ALL`，观察是否被 NACK（若 NACK，说明设备可能不支持用户存储区）。
3. 修改参数、断电重启后，检查参数是否被保持（若不保持，说明设备无用户可写 NVM）。

### 10.7.2 Store 前验证参数

执行 Store 操作前，建议先读回关键参数确认其值正确。错误的参数一旦写入 NVM，可能影响设备安全运行。

### 10.7.3 与 ON_OFF_CONFIG / OPERATION 的配合

Store 操作通常要求设备处于特定工作状态。`ON_OFF_CONFIG` 控制上电行为，`OPERATION` 控制输出使能，两者与 NVM 操作的配合关系详见第 9 章。

### 10.7.4 Host Driver 中的 NVM 策略配置

从 Datasheet 到 Host Driver Profile 的转换过程中，NVM 和写保护策略是必要配置项。Driver Profile 应包含：

- 是否支持 Store/Restore 命令
- Store 操作的保护机制（密码、解锁命令、硬件引脚）
- Store 操作的超时时间
- 参数持久化白名单

## 10.8 本章小结

| 要点 | 说明 |
|------|------|
| 三层模型 | Factory Default + User Store + Operating Memory，各层独立 |
| 上电加载 | Factory Default → User Store 覆盖 → Operating Memory |
| `STORE_USER_ALL` | RAM → User Store，保存用户配置 |
| `RESTORE_USER_ALL` | User Store → RAM，恢复用户配置 |
| `RESTORE_DEFAULT_ALL` | Factory Default → RAM，恢复出厂配置 |
| `STORE_DEFAULT_ALL` | 通常被禁用，防止覆盖出厂基线 |
| 写入限制 | NVM 有寿命上限，应集中写入、避免高频操作 |

编程示例详见第 16 章。Store/Restore 命令的数据格式遵循 PMBus 规范（详见第 5 章），总线传输协议详见第 4 章。
