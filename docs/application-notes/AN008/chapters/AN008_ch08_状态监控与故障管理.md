# 第 8 章 状态监控与故障管理

> PMBus 状态监控与故障管理是保障电源系统可靠运行的核心机制。本章讲解 PMBus 分层状态寄存器体系的结构、7 个 STATUS 寄存器的位域含义、Fault 与 Warning 的区别、FAULT_RESPONSE 配置方法，以及 CLEAR_FAULTS 命令的使用。掌握本章内容后，读者将能够在主机端实现完整的故障检测、诊断与恢复流程。

---

## 8.1 PMBus 状态寄存器体系

PMBus 采用**分层状态寄存器**结构，而非单一的故障标志位。这种设计允许主机先进行快速概览，再根据需要逐级深入定位具体故障，有效减少总线流量。

### 8.1.1 状态寄存器层级结构

状态寄存器分为两个层级：

```text
第一层（概览层）
  STATUS_BYTE (0x78)   — 8-bit 总体概览
  STATUS_WORD (0x79)   — 16-bit 扩展概览

第二层（详情层）
  STATUS_VOUT (0x7A)        — 输出电压状态
  STATUS_IOUT (0x7B)        — 输出电流状态
  STATUS_INPUT (0x7C)       — 输入电压状态
  STATUS_TEMPERATURE (0x7D) — 温度状态
  STATUS_CML (0x7E)         — 通信 / 存储器 / 逻辑状态
```

第一层寄存器中的每一位（或几位）对应一个第二层寄存器。当某个类别出现故障或警告时，第一层对应位被置位，主机据此决定是否需要进一步读取对应的第二层寄存器。

### 8.1.2 推荐的状态读取流程

主机端的故障监控应遵循以下流程：

1. **周期性读取** `STATUS_WORD (0x79)` 作为健康检查入口
2. 如果 `STATUS_WORD` 为非零值，检查高字节和低字节中哪些位被置位
3. 根据置位情况，读取对应的第二层 `STATUS_xxx` 寄存器定位具体故障
4. 读取关键遥测数据（`READ_VOUT`、`READ_IOUT`、`READ_TEMPERATURE_1` 等），记录故障现场
5. 必要时执行 `CLEAR_FAULTS (0x03)` 清除锁存状态
6. 再次读取 `STATUS_WORD`，确认故障是否由持续存在的实时条件触发

> **提示**: `STATUS_WORD` 是最有效的健康检查入口。建议在系统空闲时定期读取，仅在 `STATUS_WORD` 非零时才查询详细状态寄存器，以减少总线流量。

## 8.2 STATUS_BYTE 与 STATUS_WORD

### 8.2.1 STATUS_BYTE（0x78）

`STATUS_BYTE` 提供 8-bit 的总体状态概览，每个位对应一类故障或状态。它仅反映电源模块本身的状态，不包含输出电压的详细信息（输出电压的状态通过 `STATUS_VOUT` 反映）。

| 位 | 名称 | 说明 |
|----|------|------|
| 7 | BUSY | 模块正在处理命令或执行内部操作 |
| 6 | OFF | 模块输出处于关闭状态 |
| 5 | VOUT fault | 输出电压存在故障条件（详见 STATUS_VOUT） |
| 4 | IOUT fault | 输出电流存在故障或警告条件（详见 STATUS_IOUT） |
| 3 | INPUT fault | 输入电压存在故障条件（详见 STATUS_INPUT） |
| 2 | TEMPERATURE fault | 温度存在故障或警告条件（详见 STATUS_TEMPERATURE） |
| 1 | CML fault | 通信、存储器或逻辑存在错误（详见 STATUS_CML） |
| 0 | OTHER | 厂商特定故障（Omnion Power 模块不支持此位） |

[TODO: 图表 — STATUS_BYTE 位域映射图]
> 图中应包含: 8-bit 位域图，标注 Bit 7~Bit 0 的名称

**传输类型**: Read Byte

**访问权限**: 只读

> **注意**: `STATUS_BYTE` 不包含 `STATUS_VOUT` 的信息。若需同时获取总览和输出电压状态，应使用 `STATUS_WORD`。

### 8.2.2 STATUS_WORD（0x79）

`STATUS_WORD` 是一个 16-bit 寄存器，由高字节（多类别故障摘要）和低字节（混合状态位）组合而成。一次读取即可获取系统级状态概览。

> **注意**: PMBus 规范定义 `STATUS_WORD = STATUS_BYTE + STATUS_VOUT`，但 Omnion Power 模块的实际实现中，低字节并非 `STATUS_VOUT` 的直接映射，而是混合了 OFF、IOUT Overcurrent、VIN Undervoltage、TEMPERATURE、CML 等多类别状态位。需要获取各子状态寄存器的完整信息时，应直接读取对应的 `STATUS_xxx` 命令。

```
STATUS_WORD = [高字节（Bit 15:8）] + [低字节（Bit 7:0）]
```

传输时低字节先传（Little-Endian），即读取返回的第一个字节为低字节，第二个字节为高字节。

**传输类型**: Read Word

#### 高字节（多类别故障摘要）

| 位 | 名称 | 说明 |
|----|------|------|
| 15 | VOUT fault | 输出电压存在故障条件（对应 STATUS_VOUT） |
| 14 | IOUT/POUT fault | 输出电流或功率存在故障或警告条件（对应 STATUS_IOUT） |
| 13 | INPUT fault | 输入电压存在故障条件（对应 STATUS_INPUT） |
| 12 | MFR_SPECIFIC | 厂商特定故障（Omnion Power 模块不支持此位） |
| 11 | POWER_GOOD# negated | 电源正常信号被取反（PGOOD 为无效状态） |
| 10 | FANS | 风扇故障（Omnion Power 模块不支持此位） |
| 9 | OTHER | 其他故障（Omnion Power 模块不支持此位） |
| 8 | UNKNOWN | 未知故障（Omnion Power 模块不支持此位） |

#### 低字节（混合状态位）

| 位 | 名称 | 说明 |
|----|------|------|
| 7 | — | 不支持 |
| 6 | OFF | 模块输出处于关闭状态 |
| 5 | VOUT Overvoltage Fault | 输出过压故障（对应 STATUS_VOUT Bit 7） |
| 4 | IOUT Overcurrent Fault | 输出过流故障（注意：此位在 STATUS_WORD 低字节中反映 IOUT 状态） |
| 3 | VIN Undervoltage Fault | 输入欠压故障 |
| 2 | TEMPERATURE fault | 温度故障 |
| 1 | CML fault | 通信 / 存储器故障 |
| 0 | 保留 | 不支持 |

> **注意**: `STATUS_WORD` 的低字节并非 `STATUS_VOUT` 寄存器的直接映射。低字节中混合了 OFF、IOUT Overcurrent、VIN Undervoltage 等信息。需要获取各子状态寄存器的完整信息时，应直接读取对应的 `STATUS_xxx` 命令。

## 8.3 第二层状态寄存器详解

### 8.3.1 STATUS_VOUT（0x7A）

`STATUS_VOUT` 报告与输出电压相关的所有故障和警告条件。

| 位 | 名称 | 说明 |
|----|------|------|
| 7 | VOUT OV Fault | 输出过压故障：VOUT 超过 `VOUT_OV_FAULT_LIMIT`，模块已执行保护动作（关断） |
| 6 | VOUT OV Warning | 输出过压警告（Omnion Power 模块不支持此位） |
| 5 | VOUT UV Warning | 输出欠压警告（Omnion Power 模块不支持此位） |
| 4 | VOUT UV Fault | 输出欠压故障：VOUT 低于欠压故障阈值 |
| 3 | VOUT MAX Warning | VOUT 超过 `VOUT_MAX` 警告阈值（Omnion Power 模块不支持此位） |
| 2 | TON_MAX Fault | 启动超时故障（Omnion Power 模块不支持此位） |
| 1 | TOFF_MAX Warning | 关断超时警告（Omnion Power 模块不支持此位） |
| 0 | VOUT Tracking Error | 电压跟踪误差（Omnion Power 模块不支持此位） |

**传输类型**: Read Byte

**实际支持**: Bit 7（VOUT OV Fault）和 Bit 4（VOUT UV Fault）已实现，其余位在 Omnion Power 模块中标记为不支持。

> **提示**: VOUT 过压故障触发后，模块将根据 `VOUT_OV_FAULT_RESPONSE (0x41)` 的配置执行关断或重启动作。具体行为取决于 Response 和 Retry Setting 的配置值。

### 8.3.3 STATUS_INPUT（0x7C）

`STATUS_INPUT` 报告与输入电压相关的故障条件。

| 位 | 名称 | 说明 |
|----|------|------|
| 7 | VIN OV Fault | 输入过压故障：VIN 超过 `VIN_OV_FAULT_LIMIT` |
| 6 | VIN OV Warning | 输入过压警告（Omnion Power 模块不支持此位） |
| 5 | VIN UV Warning | 输入欠压警告（Omnion Power 模块不支持此位） |
| 4 | VIN UV Fault | 输入欠压故障：VIN 低于 `VIN_OFF` 阈值 |

| 1 | IIN OC Warning | 输入过流警告（Omnion Power 模块不支持此位） |
| 0 | PIN OP Warning | 输入功率过载警告（Omnion Power 模块不支持此位） |

### 8.3.5 STATUS_CML（0x7E）

`STATUS_CML`（Communication, Memory, Logic）报告总线通信层面的错误，与电源输出运行状态无关。此类错误通常由主机端的命令或数据问题引起。

| 位 | 名称 | 说明 |
|----|------|------|
| 7 | INVALID_CMD | 无效或不支持的命令：主机发送了模块不认识的命令码 |
| 6 | INVALID_DATA | 无效或不支持的数据：命令被识别但数据超出合法范围 |
| 5 | PEC_FAILED | 包错误校验失败：PEC 不匹配，事务被拒绝且命令未执行 |
| 4 | MEMORY_FAULT | 存储器故障（Omnion Power 模块不支持此位） |
| 3 | PROCESSOR_FAULT | 处理器故障（Omnion Power 模块不支持此位） |
| 2 | 保留 | 不支持 |
| 1 | OTHER_COMM_FAULT | 其他通信故障（Omnion Power 模块不支持此位） |
| 0 | OTHER_MEMORY_LOGIC_FAULT | 其他存储器或逻辑故障（Omnion Power 模块不支持此位） |

**传输类型**: Read Byte

**实际支持**: Bit 7（INVALID_CMD）、Bit 6（INVALID_DATA）和 Bit 5（PEC_FAILED）已实现。

> **提示**: `STATUS_CML` 中的错误与电源运行状态是独立的。命令被拒绝不意味着电源输出存在异常，仅表示总线通信过程中出现了问题。主机应在关键操作后定期检查 `STATUS_CML` 以发现通信异常。PEC 的计算方法详见第 6 章。

**主机响应与 STATUS_CML 的关系**:

| 条件 | 设备总线响应 | STATUS_BYTE Bit 1 | STATUS_CML |
|------|------------|-------------------|------------|
| 支持的命令，有效数据 | ACK + 正常响应 | 不变 | 不变 |
| 不支持的命令 | ACK，设置标志 | 置位 | Bit 7 = 1 |
| 无效数据（越界等） | ACK，设置标志 | 置位 | Bit 6 = 1 |
| PEC 校验失败 | NACK | 不变 | Bit 5 = 1 |
| 写保护状态下的写操作 | 命令被忽略 | 不变 | 不变 |

## 8.4 故障保护机制

### 8.4.1 Fault 与 Warning 的区别

PMBus 将异常状态分为两个级别：

| 级别 | 触发条件 | 设备行为 | 典型场景 |
|------|----------|----------|----------|
| **Warning** | 参数接近但未越过保护阈值 | 设备**继续运行**，状态位置位 | IOUT 接近过流阈值，温度接近过温限制 |
| **Fault** | 参数越过保护阈值 | 设备**执行保护动作**（关断/重启/锁存） | VOUT 超过过压限制，IOUT 超过过流阈值，温度超过过温限制 |

**关键区别**:
- Warning 不会改变输出状态，设备继续正常工作
- Fault 会触发保护动作（通常为关断输出），模块可能尝试自动重启

> **提示**: 主机驱动不应仅依赖遥测数值判断设备状态，还应读取 STATUS 寄存器确认设备是否已执行保护动作。例如，即使遥测显示 VOUT 为 0V，也可能是模块因过压故障而关断，而非正常关机。

### 8.4.2 保护阈值命令

Omnion Power 模块支持以下保护阈值命令，用于配置各类保护的触发点。

#### 故障限制命令（FAULT_LIMIT）

故障限制定义参数越过此值时触发 Fault 级别的保护动作。

| 命令 | 命令码 | 默认值 | 范围 | 数据格式 | 对应状态位 |
|------|--------|--------|------|----------|-----------|
| VOUT_OV_FAULT_LIMIT | 0x40 | 14V | 10.9V ~ 15.99V | VOUT Linear | STATUS_VOUT Bit 7 |
| IOUT_OC_FAULT_LIMIT | 0x46 | 210A | 50A ~ 220A | Linear | STATUS_IOUT Bit 7 |
| OT_FAULT_LIMIT | 0x4F | 125°C | 26°C ~ 130°C | Linear | STATUS_TEMPERATURE Bit 7 |
| VIN_OV_FAULT_LIMIT | 0x55 | 63V | 48V ~ 65V | Linear | STATUS_INPUT Bit 7 |

数值编码方法参见第 5 章。

#### 警告限制命令（WARN_LIMIT）

警告限制定义参数越过此值时触发 Warning，设备继续运行。

| 命令 | 命令码 | 默认值 | 范围 | 数据格式 | 对应状态位 |
|------|--------|--------|------|----------|-----------|
| IOUT_OC_WARN_LIMIT | 0x4A | 200A | 25A ~ 200A | Linear | STATUS_IOUT Bit 5 |
| OT_WARN_LIMIT | 0x51 | 116°C | 25°C ~ 125°C | Linear | STATUS_TEMPERATURE Bit 6 |

#### 输入电压启动阈值（非标准 FAULT_LIMIT）

| 命令 | 命令码 | 默认值 | 范围 | 说明 |
|------|--------|--------|------|------|
| VIN_ON | 0x35 | 37V | 35V ~ 49V | 输入电压高于此值时允许模块启动 |
| VIN_OFF | 0x36 | 35V | 32V ~ 46V | 输入电压低于此值时模块关闭 |

`VIN_ON` 和 `VIN_OFF` 通过迟滞（Hysteresis）机制实现 UVLO 功能。`VIN_ON` 与 `VIN_OFF` 之间必须保持至少 2V 的差值。ON/OFF 控制详见第 9 章。

#### 保护阈值交叉检查规则

模块内部会自动检查阈值设置的合理性。以下规则必须满足：

| 规则 | 说明 |
|------|------|
| VOUT_OV_FAULT_LIMIT > VOUT_COMMAND | 过压限制必须高于输出设定点（自动覆盖：最大 = 设定点 + 2V） |
| IOUT_OC_FAULT_LIMIT > IOUT_OC_WARN_LIMIT | 故障限制必须高于警告限制 |
| OT_FAULT_LIMIT > OT_WARN_LIMIT | 故障限制必须高于警告限制 |
| VIN_ON > VIN_OFF（最小 2V 迟滞） | ON 阈值必须高于 OFF 阈值 |

> **注意**: 修改保护阈值前应联系 OmniOn Power FAE。不当的阈值设置可能导致模块或系统损坏。

### 8.4.3 故障响应配置（FAULT_RESPONSE）

`FAULT_RESPONSE` 命令定义故障触发后模块的行为。Omnion Power 模块提供三个 FAULT_RESPONSE 命令，分别对应不同类型的故障。

| 命令 | 命令码 | 适用故障类型 |
|------|--------|------------|
| VOUT_OV_FAULT_RESPONSE | 0x41 | 输出过压故障 |
| IOUT_OC_FAULT_RESPONSE | 0x47 | 输出过流故障 |
| OT_FAULT_RESPONSE | 0x50 | 过温故障 |

这三个命令使用相同的 8-bit 位域结构，分为三个字段：

#### Response 字段（Bit[7:6]）

Response 字段定义故障触发后的基本响应行为。

| 值 | 行为 |
|----|------|
| 00 | 无动作：仅记录状态，不改变输出 |
| 01 | 警告：设置 Warning 状态，不改变输出 |
| 10 | 关断并按 Retry Setting 响应（适用于非电流故障） |
| 11 | 关断并按 Retry Setting 响应（适用于电流故障） |

**Omnion Power 模块的限制**:
- `VOUT_OV_FAULT_RESPONSE`: 仅支持 `10b`
- `IOUT_OC_FAULT_RESPONSE`: 仅支持 `11b`
- `OT_FAULT_RESPONSE`: 仅支持 `10b`

> **注意**: PMBus 规范中，非电流故障（VOUT、Temperature 等）使用 Response = `10b` 表示关断，电流故障（IOUT）使用 Response = `11b` 表示关断。两者的关断行为含义相同，但编码值不同。这是规范设计的遗留差异。

#### Retry Setting 字段（Bit[5:3]）

Retry Setting 字段定义关断后的重启策略。

| 值 | 行为 |
|----|------|
| 000 | 故障时不重启 |
| 001 | 故障后延迟 1 次后重启 |
| 010 | 故障后延迟 2 次后重启 |
| ... | ... |
| 110 | 故障后延迟 6 次后重启 |
| 111 | 连续重启直到模块被关闭、断电或发生其他故障 |

**Omnion Power 模块的限制**: 仅支持 `000`（不重启）和 `111`（连续重启）。

默认配置为 `111`（连续重启），重启间隔固定为 4 秒。

#### Delay Time 字段（Bit[2:0]）

Delay Time 字段定义故障后自动恢复的间隔时间。

| 值 | 行为 |
|----|------|
| 000 | 无额外延迟（使用默认 4 秒间隔） |
| 001 | 0.5 秒额外延迟 |
| 010 | 1 秒额外延迟 |
| 011 | 2 秒额外延迟 |
| 100 | 4 秒额外延迟 |
| 101 | 8 秒额外延迟 |
| 110 | 16 秒额外延迟 |
| 111 | 32 秒额外延迟 |

**Omnion Power 模块的限制**: 仅支持 `000`（无额外延迟）。

#### 默认 FAULT_RESPONSE 配置

| 保护类型 | 命令码 | 默认值 | Response | Retry Setting | Delay Time | 行为描述 |
|---------|--------|--------|----------|---------------|------------|---------|
| VOUT OV | 0x41 | 0xB8 | 10b | 111 | 000 | 关断后自动重启，4 秒间隔 |
| IOUT OC | 0x47 | 0xF8 | 11b | 111 | 000 | 关断后自动重启，4 秒间隔 |
| OT | 0x50 | 0xB8 | 10b | 111 | 000 | 关断后自动重启，直到关闭 / 断电 |

完整的 FAULT_RESPONSE 位域映射参见附录 E。

> **提示**: `FAULT_RESPONSE` 为位域格式，修改时应先读取当前值，仅修改目标字段，再写回完整字节，避免意外改变其他字段的状态。

## 8.5 告警与故障的处理策略

### 8.5.1 Warning 处理策略

Warning 表示参数接近保护阈值，但设备仍在正常运行。主机的处理策略应包括：

- **记录日志**: 将 Warning 事件及其对应的遥测数据记录到系统日志
- **发送通知**: 根据系统需求向上层管理软件发送通知
- **预防性措施**: 考虑降低负载、增加散热等预防性操作
- **持续监控**: 缩短遥测轮询间隔，密切关注参数变化趋势

### 8.5.2 Fault 处理策略

Fault 表示参数已越过保护阈值，模块已执行保护动作（通常为关断输出）。主机的处理策略应包括：

- **记录故障现场**: 读取所有 STATUS 寄存器和关键遥测数据
- **判断故障原因**: 根据状态位和遥测数据分析故障根因
- **评估恢复条件**: 确认故障条件是否已消除（例如温度是否已降到安全范围）
- **执行恢复操作**: 如条件允许，执行 `CLEAR_FAULTS` 并通过 `OPERATION` 命令重新使能输出
- **故障计数**: 统计故障发生次数，超过阈值时触发系统级告警

> **注意**: 如果模块配置了自动重启（Retry Setting = 111），模块可能在主机介入之前已自行尝试恢复。主机应在检测到 Fault 后尽快读取状态，避免错过故障现场的遥测数据。

### 8.5.3 故障响应状态机

完整的故障处理状态机应包含以下阶段：

1. **正常监控** — 周期性读取 `STATUS_WORD` 和遥测数据
2. **Warning 检测** — 发现 Warning 位后记录日志并提高监控频率
3. **Fault 检测** — 发现 Fault 位后立即采集故障现场
4. **故障诊断** — 分析故障原因，评估是否可恢复
5. **故障恢复** — 执行 `CLEAR_FAULTS` → 检查状态 → 重新使能输出
6. **持续锁定** — 对于不可恢复故障，保持关闭状态并通知上层系统

详细的故障响应状态机设计和 Python 编程示例参见第 14 章和第 16 章。

## 8.6 CLEAR_FAULTS 命令

### 8.6.1 功能概述

`CLEAR_FAULTS (0x03)` 是 PMBus 故障管理中的关键命令，用于清除模块中锁存的故障状态。

**传输类型**: Send Byte（主机发送命令码，无数据阶段）

**执行效果**:
1. 清除所有 STATUS 寄存器中已锁存的位
2. 释放 SMBALERT# 信号（如果当前被拉低）
3. 将模块从锁存关断（Latch-off）状态中释放

### 8.6.2 CLEAR_FAULTS 不是"修复故障"

`CLEAR_FAULTS` 仅清除**锁存的状态标志**，并不消除导致故障的物理条件。如果输入欠压、输出过流、温度过高等条件仍然存在，相关 STATUS 位可能在清除后立即重新置位。

> **重要**: 不要将 `CLEAR_FAULTS` 理解为"修复故障"。它的作用类似于"确认已读"——告诉模块主机已经知晓并处理了故障状态。

### 8.6.3 CLEAR_FAULTS 与 SMBALERT# 的关系

模块在检测到故障或警告条件时拉低 SMBALERT# 引脚通知主机。`CLEAR_FAULTS` 会释放 SMBALERT# 信号，但前提是触发 SMBALERT# 的条件已消除（即 STATUS 寄存器中无活跃的故障/警告位）。

SMBALERT# 的完整使用方法详见第 7 章。

### 8.6.4 推荐的故障恢复流程

主机端应按以下顺序执行故障恢复：

1. 读取 `STATUS_WORD` 和相关 `STATUS_xxx` 寄存器，确定故障类型
2. 读取关键遥测数据（`READ_VIN`、`READ_VOUT`、`READ_IOUT`、`READ_TEMPERATURE_1`），评估故障现场
3. 判断故障条件是否已消除：
   - 如果条件仍存在 → 不执行 `CLEAR_FAULTS`，等待条件消除
   - 如果条件已消除 → 进入下一步
4. 执行 `CLEAR_FAULTS (0x03)`
5. 再次读取 `STATUS_WORD`，确认所有故障位已清除
6. 如果需要重新使能输出，通过 `OPERATION (0x01)` 命令将 Bit 7 置为 1

ON/OFF 控制详见第 9 章。故障恢复的 Python 编程示例参见第 16 章。

## 8.7 黑盒故障记录

Omnion Power 模块包含基于 D-flash 的**黑盒功能**（Black Box），可自动记录最近的故障事件。黑盒功能在模块掉电后数据不丢失，为主机端的事后分析提供关键信息。

### 8.7.1 功能特性

| 参数 | 值 |
|------|-----|
| 最大事件数 | 20 |
| 擦除周期 | 高达 120°C 热点温度下可擦除 20K 次 |
| 排除事件 | VIN UVLO 事件不记录在黑盒中 |
| 故障时间 | 从 VOUT 开启起经过的时间，单位为秒 |

### 8.7.2 事件记录格式

每个故障事件占用 20 字节，记录故障发生时刻的关键参数快照：

| 地址偏移 | 内容 | 说明 |
|----------|------|------|
| 0 | EVENT# | 事件序号 |
| 1 | Status_Word_High_Byte | STATUS_WORD 高字节 |
| 2 | Status_Word_Low_Byte | STATUS_WORD 低字节 |
| 3 | Status_Vout | STATUS_VOUT |
| 4 | Status_Iout | STATUS_IOUT |
| 5 | Status_Input | STATUS_INPUT |
| 6 | Status_Temperature | STATUS_TEMPERATURE |
| 7 | Status_CML | STATUS_CML |
| 8~9 | VIN_data | 输入电压读数（高字节 + 低字节） |
| 10~11 | VOUT_data | 输出电压读数（高字节 + 低字节） |
| 12~13 | IOUT_data | 输出电流读数（高字节 + 低字节） |
| 14~15 | TEMPERATURE_data | 温度读数（高字节 + 低字节） |
| 16~19 | fault_time | 故障时间（4 字节，单位：秒） |

> **提示**: 黑盒数据通过厂商特定命令读取。每次故障事件会自动记录，无需主机干预。该功能对定位间歇性故障尤为重要。
