# 第 13 章 上电与启动行为

> 本章描述 Omnion Power 数字电源模块从 VIN 上电到 PMBus 通信可用的完整启动过程，包括上电时序、PGOOD 信号行为、上电默认值以及 NVM 自动恢复机制。理解启动行为是正确编写主机初始化序列的基础。

---

## 13.1 上电时序

### 13.1.1 VIN 上电到通信使能的时序关系

模块上电是一个分阶段的过程。从 VIN 施加到模块引脚开始，经历内部电路初始化、PMBus 控制器就绪，最终主机才能通过 PMBus 总线与模块正常通信。

完整上电过程可分为以下阶段：

```text
阶段 1: VIN 施加
  ├── 输入电容充电
  ├── 内部 LDO / 偏置电路启动
  └── 内部 MCU / DSP 开始执行复位向量

阶段 2: 内部初始化
  ├── 时钟与外设初始化
  ├── ADC 校准因子从 NVM 加载
  └── GPIO（SDA、SCL、SMBALERT#、PG）方向与默认状态配置

阶段 3: NVM 参数恢复
  ├── 从 Default Store 加载出厂参数到 Operating Memory（RAM）
  ├── 若 User Store 有效，覆盖 RAM 中的对应参数
  └── 参数交叉检查与约束仲裁

阶段 4: PMBus 控制器就绪
  ├── PMBus 从设备地址锁存（ADDR1 引脚电阻采样）
  ├── SDA / SCL 进入高阻态（由外部上拉电阻拉至 idle high）
  └── 模块开始响应 PMBus 事务

阶段 5: 输出启动（如满足条件）
  ├── 检查 VIN ≥ VIN_ON 阈值
  ├── 检查 ON/OFF 引脚状态
  ├── 检查 OPERATION 命令默认值
  ├── 等待 TON_DELAY
  └── 输出电压开始上升（TON_RISE）
```

### 13.1.2 通信使能条件

主机在以下所有条件满足后，才能可靠地与模块进行 PMBus 通信：

| 条件 | 描述 |
|------|------|
| VIN ≥ VIN_ON + 安全裕量 | 输入电压必须超过 VIN_ON 阈值，模块内部偏置电路才能稳定工作 |
| PMBus 控制器初始化完成 | 从 VIN 施加起通常需要数毫秒到数十毫秒，具体值参见产品 Datasheet |
| SDA / SCL 处于空闲高电平 | 由外部上拉电阻维持，表明总线未被其他设备占用 |
| 地址已锁存 | ADDR1 引脚电阻值在上电时被采样，此后不再变化直到下次复位 |

> **提示**: 从 VIN 施加到 PMBus 通信可用存在一个不可压缩的延迟窗口。主机固件应在上电后插入足够的等待时间，或采用轮询方式（发送已知命令并检测 ACK）来判断模块是否就绪。不建议在模块上电后立即发送命令。

### 13.1.3 通信不可用时段

以下时段内模块不响应 PMBus 事务，主机的发送将导致 NACK 或无响应：

| 时段 | 原因 | 建议处理方式 |
|------|------|-------------|
| VIN 上升过程中 | 内部偏置电压未达到工作阈值 | 等待 VIN 稳定后再发起通信 |
| 上电初始化期间 | 内部 MCU 正在执行复位和初始化代码 | 插入足够延时（通常 ≥ 50ms），具体值参见 Datasheet |
| STORE / RESTORE 执行期间 | NVM 写入/读取操作需要数十到数百毫秒 | 等待操作完成后再发送后续命令 |
| NVM STORE 操作期间 | EEPROM 写入期间模块可能 NACK | 参见第 10 章 NVM 操作注意事项 |
| 模块处于 OFF 状态 | 部分命令在 OFF 状态下不响应 | 检查 STATUS_WORD Bit 6 (OFF) 判断模块状态 |

> **警告**: 在通信不可用时段内持续发送 PMBus 事务可能导致主机超时错误累积，影响系统稳定性。建议在初始化阶段使用递增超时重试策略，而非固定频率轮询。

> **编程提示**: 主机端初始化序列中推荐的处理流程见第 16 章 Python 编程示例，第 14 章主机端驱动开发指南也提供了 Bring-up Checklist。

## 13.2 PGOOD 信号时序

Power Good（PGOOD）信号是模块向系统报告输出电压状态的重要指示。Omnion Power 模块的 PGOOD 引脚为开漏输出结构，需外部上拉电阻（推荐 10kΩ）连接至 3.3V 电源。

### PGOOD 极性

PGOOD 信号的极性由 MFR_PGOOD_POLARITY (0xE2) 命令的 Bit 0 控制（详见第 9 章 PGOOD 配置）：

| MFR_PGOOD_POLARITY Bit 0 | 极性 | PGOOD 引脚行为 |
|--------------------------|------|---------------|
| 1（默认） | 正逻辑 | VOUT 正常时引脚为 HIGH（释放开漏），异常时拉低 |
| 0 | 负逻辑 | VOUT 正常时引脚为 LOW（拉低开漏），异常时释放 |

### PGOOD 断言/取消断言阈值

| 参数 | 命令 | 默认值 | 范围 | 说明 |
|------|------|--------|------|------|
| PGOOD ON 阈值 | POWER_GOOD_ON (0x5E) | 11.4V | 9.2V ~ 11.7V | VOUT 上升到此值后 PGOOD 断言 |
| PGOOD OFF 阈值 | POWER_GOOD_OFF (0x5F) | 9.8V | 7.6V ~ 10.1V | VOUT 下降到此值后 PGOOD 取消断言 |

> **注意**: POWER_GOOD_ON 必须大于 POWER_GOOD_OFF 至少 0.5V，模块内部会自动执行此交叉检查。

上电过程中 PGOOD 信号的典型行为：

1. **上电初期**: PGOOD 引脚处于 Hi-Z 状态（由外部上拉电阻拉至默认电平），此时模块尚未建立输出
2. **VOUT 上升期间**: VOUT 从 0 开始上升，尚未达到 PGOOD ON 阈值，PGOOD 保持默认状态
3. **VOUT 达到 POWER_GOOD_ON**: PGOOD 信号按照当前极性配置断言（正逻辑下释放为 HIGH）
4. **正常稳态**: PGOOD 保持断言状态，系统可安全使用输出电压
5. **故障/关断时**: VOUT 跌至 POWER_GOOD_OFF 阈值以下，PGOOD 取消断言，通知下游负载

### PGOOD 与保护机制的关联

当模块因保护动作（OVP、OCP、OTP 等）关断输出时，PGOOD 会随之取消断言。故障响应的详细配置参见第 8 章。

> **提示**: 主机可通过读取 STATUS_WORD (0x79) 的 Bit 11（POWER_GOOD# 取反）来确认 PGOOD 状态。当 STATUS_WORD Bit 11 = 1 时，表示 PGOOD 处于取消断言状态。

## 13.3 上电默认值

模块上电后，所有运行参数恢复为 NVM 中存储的值（详见 13.4 节）。以下表格列出出厂默认值，即未执行过任何 STORE 操作时的参数初始状态。

### 输出电压相关默认值

| 参数 | 命令 | 命令码 | 默认值 | 范围 | 单位 |
|------|------|--------|--------|------|------|
| 输出电压设定点 | VOUT_COMMAND | 0x21 | 12.000 | 9.500 ~ 12.500 | V |
| 高裕量值 | VOUT_MARGIN_HIGH | 0x25 | 12.000 | 8.200 ~ 13.300 | V |
| 低裕量值 | VOUT_MARGIN_LOW | 0x26 | 11.400 | 8.100 ~ 13.200 | V |
| VOUT 模式 | VOUT_MODE | 0x20 | 0x14 | — | — |

> **说明**: VOUT_MODE 默认值为 0x14，表示线性模式、指数 N = -12，即分辨率 0.244 mV。

### 保护阈值默认值

| 参数 | 命令 | 命令码 | 默认值 | 范围 | 单位 |
|------|------|--------|--------|------|------|
| 输出过压限制 | VOUT_OV_FAULT_LIMIT | 0x40 | 14 | 10.9 ~ 15.99 | V |
| 输出过流限制 | IOUT_OC_FAULT_LIMIT | 0x46 | 210 | 50 ~ 220 | A |
| 输出过流警告限制 | IOUT_OC_WARN_LIMIT | 0x4A | 200 | 25 ~ 200 | A |
| 过温限制 | OT_FAULT_LIMIT | 0x4F | 125 | 26 ~ 130 | °C |
| 过温警告限制 | OT_WARN_LIMIT | 0x51 | 116 | 25 ~ 125 | °C |
| 输入过压限制 | VIN_OV_FAULT_LIMIT | 0x55 | 63 | 48 ~ 65 | V |

> **注意**: 保护阈值的交叉检查规则和故障响应默认行为详见第 8 章。客户在修改保护阈值前应联系 Omnion Power FAE，不当设置可能导致模块或系统损坏。

### 输入电压与启动默认值

| 参数 | 命令 | 命令码 | 默认值 | 范围 | 单位 |
|------|------|--------|--------|------|------|

| 启动延迟 | TON_DELAY | 0x60 | 0 | 0 ~ 500 | ms |
| 上升时间 | TON_RISE | 0x61 | 25 | 12 ~ 500 | ms |

### PGOOD 默认值

| 参数 | 命令 | 命令码 | 默认值 | 范围 | 单位 |
|------|------|--------|--------|------|------|
| PGOOD ON 阈值 | POWER_GOOD_ON | 0x5E | 11.4 | 9.2 ~ 11.7 | V |
| PGOOD OFF 阈值 | POWER_GOOD_OFF | 0x5F | 9.8 | 7.6 ~ 10.1 | V |
| PGOOD 极性 | MFR_PGOOD_POLARITY | 0xE2 | 0x01（正逻辑） | — | — |

### 控制命令默认值

| 参数 | 命令 | 命令码 | 默认值 | 说明 |
|------|------|--------|--------|------|
| ON/OFF 与裕量控制 | OPERATION | 0x01 | 0x88 | Bit 7 = 1 (ON)，Bits[5:4] = 00 (无裕量) |
| ON/OFF 配置 | ON_OFF_CONFIG | 0x02 | 0x1D | 负逻辑，控制引脚始终有效 (cpa=1) |
| 写保护 | WRITE_PROTECT | 0x10 | 0x00 | 未通过此命令启用写保护 |
| PMBus 能力 | CAPABILITY | 0x19 | 0xB0 | 支持 SMBALERT 和 PEC |

> **注意**: OPERATION 默认值为 0x88（Bit 7 = 1），表示模块上电后默认处于 ON 状态。实际的输出使能还取决于 ON/OFF 引脚状态（参见第 9 章 ON/OFF 控制逻辑）。

### 写保护与制造商特定默认值

| 参数 | 命令 | 命令码 | 默认值 | 说明 |
|------|------|--------|--------|------|
| 设备类型与写保护 | MFR_DEVICE_TYPE | 0xD0 | 0x014E | WPE = 1（写保护激活），包含模块名称编码 |
| PMBus 协议版本 | PMBUS_REVISION | 0x98 | 0x22 | Part I = 1.2，Part II = 1.2 |
| 厂商标识 | MFR_ID | 0x99 | "OMPW" | Block Read |

> **重要**: 上电时写保护处于激活状态（MFR_DEVICE_TYPE 中 WPE = 1）。主机在修改任何受保护参数之前，必须先通过 MFR_DEVICE_TYPE 命令清除写保护（WPE = 0）。写保护的详细机制参见第 9 章。

## 13.4 NVM 自动恢复机制

模块内部维护分层参数模型，上电时自动从非易失性存储恢复运行参数。详细的存储器模型和命令操作参见第 10 章。

### 参数恢复优先级

模块上电时，参数加载遵循以下优先级：

```text
Step 1: 从 Factory Default (NVM) 加载所有支持参数到 Operating Memory (RAM)
Step 2: 检查 User Store (NVM) 是否有效（valid flag / checksum）
Step 3: 若 User Store 有效，将 User Store 中的参数覆盖到 Operating Memory
```

**优先级规则**: User Store > Factory Default

即：如果 User Store 中保存过用户配置，上电时将使用用户配置而非出厂默认值。只有在 User Store 无效或不存在时，模块才完全使用 Factory Default。

> **提示**: 这意味着如果用户曾通过 STORE_DEFAULT_ALL 保存过自定义配置（如 VOUT_COMMAND = 11.5V），即使后续断电再上电，模块仍会以 11.5V 启动，而非出厂默认的 12.000V。

### 上电后参数验证建议

由于 NVM 自动恢复的存在，主机在系统初始化时不应假设模块处于出厂默认状态。推荐在首次通信后读取并验证关键参数：

| 建议验证的参数 | 命令 | 原因 |
|---------------|------|------|
| VOUT_COMMAND | 0x21 | 确认输出电压设定点符合系统预期 |
| VIN_ON / VIN_OFF | 0x35 / 0x36 | 确认输入电压启动/关闭阈值 |
| OPERATION | 0x01 | 确认模块默认 ON/OFF 状态 |
| ON_OFF_CONFIG | 0x02 | 确认 ON/OFF 引脚极性配置 |
| 保护阈值 | 0x40 / 0x46 / 0x4F 等 | 确认保护参数未被意外修改 |

> **警告**: 非必要不在 Bring-up 早期执行 STORE 操作。NVM 写入次数有限（EEPROM 典型寿命为数万次到十万次），频繁写入会缩短存储器使用寿命。参见第 10 章 NVM 操作注意事项和第 14 章主机端驱动开发指南中的 NVM 安全策略。

### RESTORE_DEFAULT_ALL 的语义

执行 RESTORE_DEFAULT_ALL (0x12) 命令会将 Factory Default 或 Default Store 中的配置重新加载到 Operating Memory。该命令的精确语义取决于模块内部的 NVM 实现：

| 模块类型 | RESTORE_DEFAULT_ALL 行为 |
|---------|------------------------|
| 双存储区（Factory + User） | 将 Factory Default 加载到 RAM 和 User Store，实现真正的"恢复出厂设置" |
| 单存储区（仅 Default Store） | 将 Default Store（可能已被用户覆盖）加载到 RAM，等效于"恢复上次保存的配置" |

> **注意**: 对于 Omnion Power 模块，STORE_DEFAULT_ALL (0x11) 将当前运行参数保存到 Default Store。因此，如果用户曾经执行过 STORE_DEFAULT_ALL 保存自定义配置，后续的 RESTORE_DEFAULT_ALL 恢复的是用户保存的配置，而非原始出厂值。NVM 命令的详细语义参见第 10 章。
