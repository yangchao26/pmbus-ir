## 2.1 从 I²C 到 PMBus：三层协议栈

PMBus 不是凭空出现的协议，它建立在两层已有的总线标准之上。理解这三层协议栈的关系，是掌握 PMBus 的第一步。

### 2.1.1 I²C（Inter-Integrated Circuit）简介与历史

I²C 是一种由 Philips Semiconductor（现为 NXP Semiconductors）在 1980 年代提出的**板级短距离串行通信总线**。其设计目标是：

- **减少芯片间连线数量** — 只需两根信号线
- **支持多设备共享总线** — 通过地址区分不同设备
- **简化 MCU 与外围 IC 的接口** — 统一通信方式

I²C 只使用两根信号线：

| 信号 | 全称 | 作用 |
|------|------|------|
| SCL | Serial Clock Line | 时钟线 |
| SDA | Serial Data Line | 数据线 |

I²C 在电子系统中极为普遍：EEPROM、温度传感器、RTC、ADC/DAC、OLED 显示驱动等都使用 I²C。在电源系统中，I²C 是 PMBus 的物理层基础。

### 2.1.2 SMBus（System Management Bus）：I²C 的受限超集

SMBus 由 Intel 在 1995 年提出，并由 System Management Interface Forum 维护。它针对**系统管理与监控**场景，在 I²C 的基础上进行了两个方向的修改：

**增加内容（超集）**：
- 包错误校验（Packet Error Code, PEC），基于 CRC-8
- SMBALERT# 中断信号
- 标准化的事务（Transaction）类型定义
- 总线超时（Bus Timeout）机制

**限制自由度（受限）**：
- 时钟频率范围限定为 10 kHz ~ 100 kHz
- 强制要求总线超时检测
- 电气参数更严格
- Clock Stretching 受超时约束

> **提示**: "受限超集"意味着 SMBus 既比 I²C 多了功能，又比 I²C 少了自由度。一个符合 SMBus 规范的设备通常可以在 I²C 总线上工作，但反过来不一定成立。

### 2.1.3 PMBus：在 SMBus 上叠加电源管理命令集

PMBus 由 System Management Interface Forum 制定，专用于**电源系统的数字化管理**。它定义了：

- **配置命令**：设置输出电压、过流保护阈值、软启动时间等
- **遥测命令**：读取输入电压、输出电压、输出电流、温度等
- **控制命令**：开关电源、Margin 测试、清除故障等
- **故障管理**：完整的 STATUS 寄存器和 FAULT_RESPONSE 机制

PMBus 的本质可以概括为：

```
PMBus = SMBus + 电源设备命令标准
```

因此 PMBus 继承了 SMBus 的所有物理层约束，同时在其上叠加了一套丰富的电源管理命令集。PMBus 的数据格式（如 11-bit Linear 编码）将在第 5 章中详细讲解。

## 2.2 I²C / SMBus 物理层

物理层是理解 PMBus 通信的基础。本节详细讲解信号线的电气特性、上拉电阻的设计方法，以及 SMBus 与 I²C 的电气差异。

### 2.2.1 信号线（SCL / SDA）与开漏（Open-Drain）拓扑

I²C/SMBus 总线上的所有设备共享两根信号线：SCL（时钟）和 SDA（数据）。每根线都采用**开漏（Open-Drain）输出结构**，外部通过上拉电阻连接到电源。

开漏结构的核心特点是：设备**只能主动拉低**信号线，不能主动推高。高电平由上拉电阻被动提供。这意味着：

| 设备动作 | 总线结果 |
|----------|----------|
| 所有设备释放（不拉低） | 总线为高（由上拉电阻维持） |
| 任意一个设备拉低 | 总线为低 |

这个特性被称为**线与（Wired-AND）**行为，它带来了两个关键优势：

1. **多设备安全共享** — 多个设备同时连接在同一条线上，不会因为输出冲突而损坏器件
2. **支持仲裁** — "0 覆盖 1"的特性使多主设备可以安全竞争总线控制权（详见第 2.4 节）


### 2.2.2 上拉电阻：为什么需要、如何选择

#### 为什么需要上拉电阻

开漏结构下，设备释放总线后总线处于高阻态，如果没有上拉电阻，总线电压将不确定。上拉电阻的作用是：
- 在设备释放时将总线拉回高电平
- 为 RC 充电提供电流，决定信号上升时间

#### 上拉电阻的计算方法

上拉电阻需要同时满足两个方向的约束，形成一个允许范围：**Rmin ≤ Rp ≤ Rmax**。

**约束 A：由低电平灌电流决定的最小电阻**

当总线被某个器件拉低时，电流从 VCC 通过上拉电阻流入该器件：

```
I_OL = (VCC - VOL) / Rp
```

整理得到：

```
Rp(min) = (VCC - VOL(max)) / I_OL
```

上拉电阻不能太小，否则拉低时灌电流过大，器件可能无法保证低电平指标（VOL）。

**约束 B：由上升时间决定的最大电阻**

总线电压上升过程是一个 RC 充电过程。I²C 规范中上升时间按 30% → 70% 定义，因此：

```
tr ≈ 0.8473 × Rp × Cb
```

整理得到：

```
Rp(max) = tr / (0.8473 × Cb)
```

上拉电阻不能太大，否则上升沿太慢，可能超出规范允许的最大上升时间。

#### 计算实例

以 3.3 V 系统、100 kHz Standard Mode 为例，取典型参数：
- VOL(max) = 0.4 V
- I_OL = 3 mA
- tr ≤ 1000 ns（Standard Mode 限制）
- Cb = 100 pF（短走线、少量器件的典型值）

**Step 1：计算 Rmin**

```
Rp(min) = (3.3 - 0.4) / 0.003 = 966.7 Ω
```

**Step 2：计算 Rmax**

```
Rp(max) = 1×10⁻⁶ / (0.8473 × 100×10⁻¹²) ≈ 11.8 kΩ
```

**Step 3：选择阻值**

```
966.7 Ω ≤ Rp ≤ 11.8 kΩ
```

常见可选值：2.2 kΩ、3.3 kΩ、4.7 kΩ。其中 **4.7 kΩ** 是工程中最常用的经验值，因为它在上升速度、功耗、器件驱动能力之间取得了较好的平衡。

#### 总线电容 Cb 的估算

上拉电阻计算中最难确定的通常是总线电容 Cb。它包括：

```
Cb = C_trace + ΣC_pin + C_conn + C_cable
```

| 组成部分 | 典型值 |
|----------|--------|
| 单个器件引脚电容 | 5 ~ 10 pF |
| PCB 走线电容 | 1 ~ 3 pF/cm |
| 连接器 | 2 ~ 5 pF |
| 线缆 | 50 ~ 100 pF/m |

经验估算：

| 总线负载情况 | 估计电容 |
|-------------|----------|
| 短走线，2~4 个器件 | 50 ~ 100 pF |
| 多器件 + 较长走线 | 150 ~ 250 pF |
| 板间连接或线缆 | 300 ~ 400 pF 或更高 |

#### 不同总线电容下的 Rp(max) 快速查表

以 100 kHz、tr ≤ 1 μs 为目标：

| 总线电容 Cb | Rp(max) 约值 |
|-------------|-------------|
| 50 pF | 23.6 kΩ |
| 100 pF | 11.8 kΩ |
| 150 pF | 7.9 kΩ |
| 200 pF | 5.9 kΩ |
| 300 pF | 3.9 kΩ |
| 400 pF | 2.95 kΩ |

> **提示**: 工程实践中，建议先用 4.7 kΩ 作为初始值，然后通过示波器实测 SDA/SCL 的上升时间和 VOL 来验证是否合适。最终必须以系统中最弱器件的 Datasheet 参数为准。

#### 工程选值建议

| 场景 | 建议阻值 |
|------|----------|
| 3.3 V、短线、少器件 | 4.7 kΩ |
| 总线稍重（150~250 pF） | 3.3 kΩ |
| 重负载总线（接近 400 pF） | 2.2 kΩ |
| 5 V 系统 | 4.7 kΩ 或 2.2 kΩ |

#### 通信速率的工程含义

100 kbit/s 意味着 SCL 频率约 100 kHz，每个 SCL 周期为 10 μs。I²C 每传输 1 字节需要 8 个数据位 + 1 个 ACK 位 = 9 个 SCL 周期，因此理论字节速率为：

```
100000 / 9 ≈ 11111 byte/s ≈ 11 kB/s
```

实际有效数据速率更低，因为还有 START、STOP、地址、重复 START 等协议开销。一次典型的读寄存器操作（含地址、命令码、重复 START、数据、NACK、STOP）共 36 个 bit，在 100 kHz 下耗时约 360 μs。

> **提示**: PMBus 系统的带宽瓶颈通常不在总线的原始位速率，而在于命令开销和器件内部处理时间。第 12 章将详细讨论遥测轮询的带宽预算。

### 2.2.4 SMBus 与 I²C 的电气差异

SMBus 对 I²C 的电气参数进行了更严格的限定，以保证系统管理的可靠性。

| 参数 | I²C Standard Mode | SMBus |
|------|-------------------|-------|
| 时钟频率范围 | 最高 100 kHz | **10 kHz ~ 100 kHz** |
| 最小时钟频率 | 无要求 | **10 kHz** |
| 总线超时 | 无强制要求 | **T_TIMEOUT = 35 ms** |
| 低电平累计超时 | 无要求 | **T_LOW:SEXT = 25 ms（从设备）** |
| 最大总线电容 | 400 pF | 400 pF |
| 上升时间 | ≤ 1000 ns | ≤ 1000 ns |
| 逻辑低电平 | VOL ≤ 0.4 V | VOL ≤ 0.4 V |
| 逻辑高电平 | VIH ≥ 0.7 × VDD | VIH ≥ 2.1 V（3.3 V 系统） |

> **提示**: SMBus 的最小频率要求 10 kHz 和超时要求 35 ms 是设计 PMBus 主机驱动时必须遵守的约束。如果 SCL 或 SDA 被持续拉低超过 35 ms，SMBus 设备必须复位其通信状态机。这些超时参数将在第 2.4 节中详细讨论。

## 2.3 数据链路层：位与字节传输

本节讲解 I²C/SMBus 数据链路层的核心机制：每一位如何传输、START/STOP 条件的定义、ACK/NACK 的含义、寻址方式，以及重复 START（Repeated START）。

### 2.3.1 位的传输

I²C 是**同步串行通信**，每一位数据的传输都由 SCL 时钟同步。一个时钟周期的传输过程如下：

1. **SCL 低电平期间**：发送端改变 SDA 数据
2. **SDA 稳定后**：SCL 被拉高
3. **SCL 高电平期间**：接收端采样 SDA，数据必须保持稳定
4. **采样完成后**：SCL 被拉低，准备传输下一位

> 图中应包含: SCL 和 SDA 两路波形，标注数据建立时间 tSU:DAT、数据保持时间 tHD:DAT、SCL 高低电平区域，标明 SCL 高时 SDA 必须稳定。

#### SCL 高期间 SDA 必须稳定的根本原因

这是 I²C 时序的**最核心规则**。SDA 在 SCL 高期间变化只会被解释为 START 或 STOP 条件，不会被视为有效数据。这条规则的原因有三个：

1. **同步采样** — 接收端在 SCL 高期间采样 SDA，数据变化会导致位歧义
2. **仲裁机制** — 多主设备在 SCL 高期间比较自己发送的 SDA 与总线实际 SDA，数据变化会导致仲裁失效
3. **START/STOP 检测** — START 和 STOP 条件本身就定义为 SCL 高时 SDA 的变化，如果数据也允许变化，协议将无法区分

### 2.3.2 START 条件

START 条件标志着一次通信的开始。所有从设备在检测到 START 条件后进入监听状态。

**定义**：当 **SCL 为高电平时，SDA 从高电平跳变到低电平**。

这是唯一允许 SDA 在 SCL 高期间从高变低的情况。

```
SCL  ──────────────
SDA  ────────┐_____
             START
```

START 条件必须满足的时序要求：
- SDA 的下降沿发生在 SCL 高电平期间
- START 建立时间 tSU:STA ≥ 4.7 μs（Standard Mode）

### 2.3.3 STOP 条件

STOP 条件标志着一次通信的结束，总线被释放。所有从设备在检测到 STOP 条件后回到空闲状态。

**定义**：当 **SCL 为高电平时，SDA 从低电平跳变到高电平**。

这是唯一允许 SDA 在 SCL 高期间从低变高的情况。

```
SCL  ─────────────
SDA  _____┘───────
        STOP
```

> **提示**: START 和 STOP 条件都由 Master 产生。在一次通信中，START 和 STOP 之间是有效的数据传输。没有 START，设备不会响应；没有 STOP，总线被认为处于"忙"状态。

### 2.3.4 ACK 与 NACK

I²C 采用**每字节确认**机制。发送端每发送完 8 位数据后，释放 SDA（拉高），在第 9 个 SCL 时钟周期等待接收端的响应。

**ACK（Acknowledgment）**：
- 接收端在 ACK 时钟周期内将 SDA **拉低**
- 表示数据已被正确接收

**NACK（Not Acknowledgment）**：
- 接收端在 ACK 时钟周期内**不拉低 SDA**（保持高）
- 表示数据未收到、命令不支持、或传输应结束

- Master 读取最后一个字节后发 NACK，告知 Slave 停止发送
- Slave 未识别到自己的地址
- Slave 正忙无法响应
- Slave 不支持 Master 请求的命令

### 2.3.5 字节序与位序（LSB first）

I²C/SMBus 使用 **LSB First（低位在前）** 的位传输顺序，这与大多数串行协议一致。

一个字节 8 位的传输顺序为：

```
| D7 | D6 | D5 | D4 | D3 | D2 | D1 | D0 | ACK |
```

但注意：这是**单个字节内部**的位序。对于**多字节**数据，PMBus 通常采用**大端序（Big-Endian）**，即高字节在前（先传输）。例如一个 16-bit Word 数据：

```
| Byte High (先传) | Byte Low (后传) |
```

### 2.3.6 7-bit 设备寻址 + R/W# 位

I²C/SMBus 使用 **7-bit 地址**进行设备寻址。每次通信开始后，Master 发送的第一个字节由 7 位地址和 1 位读/写方向位组成：

```
| A6 | A5 | A4 | A3 | A2 | A1 | A0 | R/W |
  ←— 7-bit 设备地址 —→  ← 方向 →
```

| R/W# 位值 | 含义 |
|-----------|------|
| 0 | 写操作（Write） |
| 1 | 读操作（Read） |

**地址范围**：
- 7-bit 地址范围：0x00 ~ 0x7F（128 个地址）
- 其中部分地址被保留：
  - 0x00（0000000）：General Call（广播地址）
  - 0x08 ~ 0x0F：保留
  - 0x01 ~ 0x07（0000 xxx）：CBUS 地址
  - 0x78 ~ 0x7F（1111 xxx）：保留给未来扩展

在 SMBus 中：
- 0x08（0001000）：SMBus Host 地址
- 0x0A（0001100）：Alert Response Address（ARA）

PMBus 设备地址通常可以通过硬件引脚或 NVM 配置来设置，具体范围参见各产品 Datasheet。

### 2.3.7 REPEATED START（Sr）

重复 START（Repeated START，记为 Sr）允许 Master 在不发出 STOP 条件的情况下，重新发起一次通信。其定义与 START 条件完全相同：SCL 高时 SDA 从高变低。

```
通信序列示例（读寄存器）：

START → Address + W → ACK → Command → ACK → Sr → Address + R → ACK → Data → NACK → STOP
```

Sr 的关键用途是**改变读写方向**，而不释放总线。这在 PMBus 读取操作中极为常见：

1. Master 先以 Write 方式发送命令码（指定要读取哪个寄存器）
2. Master 发出 Sr（不释放总线，其他 Master 不会趁机抢占）
3. Master 再以 Read 方式读取数据

> **提示**: 如果不使用 Sr，而是先 STOP 再重新 START，总线在两次通信之间会有一段空闲时间。这段时间内其他 Master 可能会抢占总线。Sr 通过保持总线的"忙"状态，避免了这个问题。

## 2.4 SMBus 高级特性

SMBus 在 I²C 基础上增加了几项关键特性，使其更适合系统管理场景。这些特性在 PMBus 系统中至关重要。

### 2.4.1 Clock Stretching

Clock Stretching（时钟拉伸）是 I²C/SMBus 的一项重要机制。在通信过程中，**从设备可以拉低 SCL 来暂停时钟**，从而延迟通信的进行。

Clock Stretching 的典型使用场景：
- 从设备需要时间处理接收到的命令
- 从设备正在准备要发送的数据
- 从设备正在执行内部 NVM 操作

**I²C 与 SMBus 的差异**：
- I²C 允许从设备无限期拉低 SCL
- SMBus 对 Clock Stretching 时间设有上限（受超时机制约束）

> **提示**: 在 PMBus 电源设备中，Clock Stretching 可能在准备 Read Word 数据、处理 NVM Store/Restore、或故障发生后状态寄存器同步时发生。但不建议将其作为常规限速手段。若遥测数据准备时间较长，更好的做法是使用 Shadow Register，将实时采样与 PMBus 访问解耦。

### 2.4.2 总线超时（Bus Timeout）

总线超时是 SMBus 最关键的可靠性机制之一。I²C 没有强制超时要求，而 SMBus 定义了严格的超时规则，目的是**防止总线死锁导致整个系统卡死**。

#### SMBus 超时参数

| 超时类型 | 符号 | 时间 | 含义 |
|----------|------|------|------|
| 从设备时钟低扩展超时 | T_LOW:SEXT | 25 ms | 从设备持续拉低 SCL 的最大时间 |
| 从设备时钟低累计超时 | T_LOW:MEXT | 25 ms | 从设备在单次传输中累计拉低 SCL 的最大时间 |
| 总线超时 | T_TIMEOUT | 35 ms | SCL 或 SDA 被拉低的最大时间 |

#### 超时触发后的行为

当检测到超时后：
- **从设备**：必须复位其通信状态机，释放 SCL/SDA
- **主机**：应中止当前事务，执行总线恢复流程

#### PMBus 主机驱动的设计建议

- 为每个事务设置独立的超时计时
- 对超时、NACK、总线忙做有限次重试
- 如果连续超时，应标记设备离线或降级轮询
- 对 NVM 操作设置更长但明确的等待窗口

> **提示**: 主机驱动中的超时实现是 PMBus 系统可靠性的关键。超时时间应大于从设备的最大处理时间，但必须小于 SMBus 规定的 35 ms 总线超时。第 14 章将详细讨论主机端驱动开发中的超时设计。

### 2.4.3 总线恢复（Bus Recovery）

当总线因为异常情况被锁定（SDA 或 SCL 被某个设备持续拉低），需要通过总线恢复流程来恢复正常通信。

#### 总线锁定的常见原因

- 主机在一次读事务中途复位或异常退出
- 从设备仍在等待额外的 SCL 时钟，持续驱动 SDA 为低
- 噪声导致主从设备状态机不同步
- 设备 firmware 卡在 Clock Stretching 中
- 热插拔或电源时序导致总线缓冲器（Bus Buffer）异常

#### 标准总线恢复流程

```
1. 停止当前 SMBus controller 的事务
2. 将 SCL/SDA 切换到 GPIO 模式，或使用 controller 内置的 bus recovery 功能
3. 确认 SCL 可以被释放为高
4. 发送最多 9 个 SCL 时钟脉冲，尝试让从设备完成其当前字节并释放 SDA
5. 检测 SDA 是否被释放为高
6. 生成 STOP 条件
7. 重新初始化 SMBus/I²C controller
8. 重新执行设备发现（Discovery）或标记设备 degraded/offline
```

> **提示**: 如果 SCL 本身被硬件持续拉低，9-clock 恢复流程不一定有效。此时需要隔离故障设备、复位电源域、或通过总线缓冲器处理。PMU/Hot-swap 控制器通常可以在固件层面实现自动电源循环（Power Cycle）来恢复。

### 2.4.4 SMBus 与 I²C 协议差异总结表

| 特性 | I²C | SMBus |
|------|-----|-------|
| 设计目标 | 通用芯片间通信 | 系统管理 |
| 时钟频率范围 | 最高 100 kHz（Standard Mode），支持 400 kHz / 1 MHz / 3.4 MHz | **10 kHz ~ 100 kHz** |
| 最小时钟频率 | 无要求 | **10 kHz** |
| 总线超时 | 无强制要求 | **T_TIMEOUT = 35 ms** |
| Clock Stretching | 允许，无时间限制 | 允许，但受 **T_LOW:SEXT = 25 ms** 约束 |
| 包错误校验（PEC） | 无 | **CRC-8** |
| SMBALERT# 中断 | 无 | **支持** |
| 标准 Transaction 类型 | 仅定义位级协议 | **定义 11 种标准事务类型** |
| 逻辑高电平阈值 | ≥ 0.7 × VDD | ≥ 2.1 V（3.3 V 系统） |
| 电压范围 | 灵活 | 规范中明确定义 |

## 2.5 PMBus 对 SMBus 的扩展

PMBus 在 SMBus 协议基础之上，增加了面向电源管理的扩展。本节简要介绍这些扩展，为后续章节的详细讲解奠定基础。

### 2.5.1 额外信号：CTRL、WP

除了标准的 SCL 和 SDA，PMBus 规范还定义了两个可选的辅助信号：

**CONTROL（CTRL）**
- 用于主机控制从设备的运行状态
- 当 CTRL 被拉低时，从设备应关闭其输出
- 这是一种硬件级的紧急关断机制，不依赖通信协议

**WRITE PROTECT（WP）**
- 用于保护非易失性存储器（NVM）中的配置参数
- 当 WP 被拉低时，从设备拒绝所有 Store 命令
- 防止意外修改设备配置

| 信号 | 方向 | 有效电平 | 功能 |
|------|------|----------|------|
| CTRL | Master → Slave | 低电平有效 | 硬件关闭输出 |
| WP | Master → Slave | 低电平有效 | 写保护 NVM |

> **提示**: CTRL 和 WP 是可选信号，是否支持取决于具体产品。CTRL 信号可以在总线通信失效时提供紧急关断能力，是系统安全设计的重要考量。WP 信号在生产校准完成后拉低，可以防止现场误操作修改设备配置。相关硬件设计将在第 3 章中详细讨论。

### 2.5.2 总线速率

PMBus 1.2/1.3 规范支持的速率：

| 速率 | 说明 |
|------|------|
| 10 kHz ~ 100 kHz | SMBus 兼容模式，所有 PMBus 设备必须支持 |
| 100 kHz | 最常用的默认速率 |
| 400 kHz（Fast Mode） | 部分设备支持，需查阅具体产品 Datasheet |

Omnion Power 产品通用特性：
- 支持 100 kHz / 400 kHz 总线速率

> **提示**: 即使设备支持 400 kHz，在长走线、多设备、大电容总线上仍建议使用 100 kHz 以保证可靠性。使用 400 kHz 时，上拉电阻可能需要降低到 2.2 kΩ 以满足更严格的上升时间要求（≤ 300 ns）。具体时序设计参见第 3 章。

### 2.5.3 GROUP 协议简介

GROUP 协议是 PMBus 的一项独特功能，允许主机通过一次事务同时控制总线上**所有设备**。

**工作机制**：
- 主机发送 General Call 地址（0x00）
- 后跟 GROUP 命令
- 总线上所有设备同时执行该命令

**典型应用场景**：
- 同时开启或关闭所有电源输出
- 同时执行 Store_Default 或 Restore_Default
- 同时清除所有设备的故障状态

> **提示**: GROUP 协议在多路电源系统中可以大幅简化管理操作。但由于所有设备同时响应，在大系统中需要注意总线负载和时序裕量。GROUP 协议的使用方法将在第 9 章中详细讨论。

### 2.5.4 SMBALERT# 中断信号

SMBALERT# 是 SMBus/PMBus 定义的中断机制，允许从设备**主动通知**主机发生了异常事件。

**信号特性**：
- SMBALERT# 是低电平有效（Active Low）的开漏信号
- 多个设备的 SMBALERT# 可以线与连接到主机的一个中断引脚
- 主机通过 SMBus 上的 Alert Response Address（ARA, 0x0A）协议来识别是哪个设备发出了中断

**典型触发事件**：
- 输出电压过压/欠压
- 输出电流过流
- 温度超限
- 输入电压异常
- 任何导致 STATUS_BYTE 变化的故障

**中断响应流程**：
```
1. 从设备检测到故障 → 拉低 SMBALERT#
2. 主机检测到 SMBALERT# 中断
3. 主机发送 ARA（0x0A + Read）事务
4. 所有发出中断的设备参与地址仲裁
5. 获胜设备返回自己的 7-bit 设备地址
6. 主机读取获胜设备的 STATUS 寄存器
7. 重复步骤 3~6 直到无更多设备响应
8. 所有中断处理完毕后 SMBALERT# 被释放
```

> **提示**: SMBALERT# 机制使 PMBus 从被动的轮询模式转变为主动的中断驱动模式，大大提高了故障响应速度。完整的中断协议细节将在第 7 章中详细讲解。

## 本章小结

本章从底层到顶层，完整介绍了 PMBus 协议栈的三层结构及其核心机制：

1. **三层协议栈**：I²C（物理层） → SMBus（事务层 + 约束） → PMBus（电源命令层）
2. **物理层**：开漏拓扑、上拉电阻计算（Rmin/Rmax 双向约束）、电气参数
3. **数据链路层**：位传输、START/STOP 条件、ACK/NACK、7-bit 寻址、LSB First、Repeated START
4. **SMBus 高级特性**：Clock Stretching、总线超时（25 ms / 35 ms）、总线恢复
5. **PMBus 扩展**：CTRL/WP 信号、总线速率、GROUP 协议、SMBALERT#

理解这些基础概念后，读者将能够在后续章节中顺利学习 PMBus 的传输协议（第 4 章）、数据格式（第 5 章）和各类命令的使用方法。
