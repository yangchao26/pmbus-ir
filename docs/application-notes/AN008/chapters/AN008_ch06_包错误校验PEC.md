# 第 6 章 包错误校验（PEC）

> 本章讲解 SMBus/PMBus 的包错误校验（Packet Error Check, PEC）机制，包括 CRC-8 多项式原理、直接计算法与查表法实现、逐字节计算过程图解，以及带 PEC 的事务时序。掌握 PEC 对保证电源管理通信可靠性至关重要——在服务器、基站等长 PCB trace、高噪声环境中，PEC 能有效防止静默数据损坏导致负载损坏。

---

## 6.1 为什么需要 PEC

PMBus 继承自 SMBus 的物理层，本质上是一种共享总线的开漏（Open-Drain）通信。在理想条件下，I²C/SMBus 的 ACK/NACK 机制已经能检测到部分传输错误，但 ACK/NACK 仅校验单个字节的接收状态，**无法检测总线上的位翻转（bit error）**。

### 6.1.1 电源管理场景下数据错误的后果

在电源管理系统中，PMBus 承载的命令直接影响电源输出：

| 错误场景 | 后果 | 严重程度 |
|----------|------|----------|
| VOUT_COMMAND 数据损坏 | 输出电压偏移，可能超出负载耐压 | 极高——烧毁负载 |
| IOUT_OC_FAULT_LIMIT 损坏 | 过流保护阈值错误，过流时无法保护 | 极高——电源烧毁 |
| OPERATION 命令损坏 | 意外关断或意外开启 | 高——系统掉电 |
| FAULT_RESPONSE 损坏 | 故障后行为异常（如持续重启） | 中——影响可用性 |

> **提示**: 与普通传感器数据不同，PMBus 不仅传输遥测读数，还传输控制命令和保护阈值。一个未检测到的位翻转可能导致输出电压从 1.0 V 变为 3.3 V，直接损坏后级负载。

### 6.1.2 什么时候需要启用 PEC

以下场景强烈建议启用 PEC：

- **服务器 / 数据中心电源**：背板走线长，噪声环境复杂，BMC 通常默认启用 PEC
- **基站长距通信**：线缆长度超过 30 cm，寄生电容和串扰显著
- **多设备并联总线**：总线电容大，信号完整性下降
- **关键负载供电**：CPU/GPU/FPGA 等对电压精度敏感的负载

对于短距离（< 10 cm）点对点通信、非关键应用，PEC 可选。

### 6.1.3 PEC 对带宽的影响

PEC 在事务末尾增加 1 字节。对于典型的 Read Word 操作：

```
无 PEC:  2 bytes 数据    → 传输开销 = 2 bytes
有 PEC:  2 bytes + 1 PEC → 传输开销 = 3 bytes（+50%）
```

对于 Write Byte：

```
无 PEC:  1 byte 数据     → 传输开销 = 1 byte
有 PEC:  1 byte + 1 PEC  → 传输开销 = 2 bytes（+100%）
```

> **提示**: 尽管 PEC 增加了传输开销，但 PMBus 事务通常较短（1~4 bytes 数据），且轮询频率较低（10 Hz ~ 100 Hz），带宽影响在实际系统中可以忽略。完整的事务时序参见第 4 章。

## 6.2 CRC-8 多项式与计算原理

### 6.2.1 PEC 使用的 CRC 算法

PEC 使用 CRC-8 校验，参数如下：

| 参数 | 值 |
|------|----|
| 多项式 | C(x) = x⁸ + x² + x + 1 |
| 十六进制表示 | 0x07 |
| 初始值 | 0x00 |
| 输入反射（RefIn） | 否 |
| 输出反射（RefOut） | 否 |
| 最终异或（XorOut） | 0x00 |

该多项式是 SMBus 3.x 规范和 PMBus 规范共同规定的标准多项式。与通信领域常用的 CRC-8-CCITT（0x07, init=0xFF）不同，SMBus PEC 的初始值为 0x00。

> **提示**: 多项式 C(x) = x⁸ + x² + x + 1 对应的二进制位模式为 `100000111`，去掉最高位的 x⁸ 后，即为 `0x07`。SMBus PEC 不使用输入/输出反射，这也是与许多其他 CRC-8 变体的重要区别。

### 6.2.2 PEC 计算范围

PEC 对整个事务中**参与数据传输的字节**计算 CRC，包含：

| 包含的字节 | 说明 |
|-----------|------|
| 从设备地址 + R/W# 位 | 每个地址阶段都包含 |
| 命令码（Command） | 命令字节 |
| 所有数据字节 | 按传输顺序 |

**不包含**的字节：

| 不包含 | 说明 |
|--------|------|
| START 条件 | 不是数据字节 |
| STOP 条件 | 不是数据字节 |
| REPEATED START | 不是数据字节 |
| ACK / NACK | 不是数据字节 |

对于读操作，由于地址字节出现两次（Write 阶段一次，Read 阶段一次），两次地址字节**都要**参与 PEC 计算。

### 6.2.3 不同事务类型的 PEC 输入字节

**Write Byte / Write Word：**

```
[Address + W] [Command] [Data1] [Data2] ...
       ↑           ↑        ↑
       │           │        └── 数据字节
       │           └── 命令码
       └── 从设备地址（左移 1 位 + W=0）
```

**Read Byte / Read Word：**

```
[Address + W] [Command] [Address + R] [Data1] [Data2] ...
       ↑           ↑           ↑          ↑
       │           │           │          └── 数据字节
       │           │           └── 从设备地址（左移 1 位 + R=1）
       │           └── 命令码
       └── 从设备地址（左移 1 位 + W=0）
```

> **注意**: Read 操作中，地址字节出现两次，一次带 Write 位，一次带 Read 位，两者都参与 PEC 计算。这是初学者最容易遗漏的地方。

## 6.3 PEC 计算实现

本节介绍两种常见的 PEC 计算方法：直接计算法和查表法。两种方法产生相同的结果，区别在于执行效率和代码复杂度。完整的 Python 实现参见第 16 章。

### 6.3.1 直接计算法

直接计算法逐位处理每个字节，原理直观。

**算法伪代码：**

```
PEC = 0x00
FOR each byte B in message:
    PEC = PEC XOR B
    FOR bit = 0 TO 7:
        IF (PEC AND 0x80) != 0:
            PEC = (PEC << 1) XOR 0x07
        ELSE:
            PEC = PEC << 1
        PEC = PEC AND 0xFF    // 保留低 8 位
RETURN PEC
```

**工作原理：**

1. 将当前 CRC 寄存器与新字节异或（XOR）
2. 对结果的 8 个位依次从最高位（MSB）到最低位（LSB）处理
3. 如果最高位为 1，则左移后异或多项式 0x07；否则仅左移
4. 处理完 8 位后，得到该字节累积后的 CRC 值
5. 对所有字节重复上述过程

### 6.3.2 查表法

查表法（Lookup Table）预先计算 256 种可能的字节输入对应的 CRC 值，存储在查找表中。实际计算时，对每个字节仅需一次 XOR 和一次查表操作。

**算法伪代码：**

```
PEC = 0x00
FOR each byte B in message:
    PEC = CRC_TABLE[PEC XOR B]
RETURN PEC
```

相比直接计算法，查表法将每个字节的处理从 8 次循环减少到 1 次查表，速度快约 8 倍，且代码更简洁。

### 6.3.3 逐字节计算过程图解

以下通过一个完整的示例，逐步演示 PEC 的计算过程。

**示例场景：Read Word 读取 READ_VOUT**

假设条件：

| 参数 | 值 | 说明 |
|------|----|------|
| 从设备 7-bit 地址 | 0x5A | 1011010 |
| 命令码 | 0x8B | READ_VOUT |
| 返回数据低字节 | 0x00 | — |
| 返回数据高字节 | 0x30 | — |

**第一步：确定参与 PEC 计算的字节序列**

```
地址 + Write:  0x5A << 1 | 0 = 0xB4
命令码:        0x8B
地址 + Read:   0x5A << 1 | 1 = 0xB5
数据低字节:    0x00
数据高字节:    0x30
```

> **注意**: 读操作包含两次地址字节（Write 阶段的 0xB4 和 Read 阶段的 0xB5），两者都要参与计算。

**第二步：逐字节计算（直接计算法）**

初始值：PEC = 0x00

**处理第 1 个字节 0xB4：**

```
PEC = 0x00 XOR 0xB4 = 0xB4 = 10110100

位 0: MSB=1 → (0xB4<<1) XOR 0x07 = 0x168 XOR 0x07 = 0x6F → 01101111
位 1: MSB=0 → 0x6F<<1 = 0xDE                               → 11011110
位 2: MSB=1 → (0xDE<<1) XOR 0x07 = 0x1BC XOR 0x07 = 0xBB → 10111011
位 3: MSB=1 → (0xBB<<1) XOR 0x07 = 0x176 XOR 0x07 = 0x71 → 01110001
位 4: MSB=0 → 0x71<<1 = 0xE2                               → 11100010
位 5: MSB=1 → (0xE2<<1) XOR 0x07 = 0x1C4 XOR 0x07 = 0xC3 → 11000011
位 6: MSB=1 → (0xC3<<1) XOR 0x07 = 0x186 XOR 0x07 = 0x81 → 10000001
位 7: MSB=1 → (0x81<<1) XOR 0x07 = 0x102 XOR 0x07 = 0x05 → 00000101

→ PEC = 0x05
```

**处理第 2 个字节 0x8B：**

```
PEC = 0x05 XOR 0x8B = 0x8E = 10001110

位 0: MSB=1 → 0x1B → 位 1: MSB=0 → 0x36 → 位 2: MSB=0 → 0x6C
位 3: MSB=0 → 0xD8 → 位 4: MSB=1 → 0xB7 → 位 5: MSB=1 → 0x69
位 6: MSB=0 → 0xD2 → 位 7: MSB=1 → 0xA3

→ PEC = 0xA3
```

**处理第 3 个字节 0xB5：**

```
PEC = 0xA3 XOR 0xB5 = 0x16 = 00010110

位 0~7: 0x16 → 0x2C → 0x58 → 0xB0 → 0x67 → 0xCE → 0x9B → 0x31 → 0x62

→ PEC = 0x62
```

**处理第 4 个字节 0x00：**

```
PEC = 0x62 XOR 0x00 = 0x62 = 01100010

位 0~7: 0x62 → 0xC4 → 0x89 → 0x1A → 0x34 → 0x68 → 0xD0 → 0xA9 → 0x29

→ PEC = 0x29
```

**处理第 5 个字节 0x30：**

```
PEC = 0x29 XOR 0x30 = 0x19 = 00011001

位 0~7: 0x19 → 0x32 → 0x64 → 0xC8 → 0x8B → 0x2A → 0x54 → 0xA8 → 0x4F

→ PEC = 0x4F
```

**最终结果：PEC = 0x4F**

**汇总：**

| 步骤 | 输入字节 | XOR 后 | 累积 CRC |
|------|---------|--------|----------|
| 1 | 0xB4 (Address + W) | 0xB4 | 0x05 |
| 2 | 0x8B (Command) | 0x8E | 0xA3 |
| 3 | 0xB5 (Address + R) | 0x16 | 0x62 |
| 4 | 0x00 (Data Low) | 0x62 | 0x29 |
| 5 | 0x30 (Data High) | 0x19 | **0x4F** |

**第三步：用查表法验证**

```
PEC = CRC_TABLE[0x00 XOR 0xB4] = CRC_TABLE[0xB4] = 0x05
PEC = CRC_TABLE[0x05 XOR 0x8B] = CRC_TABLE[0x8E] = 0xA3
PEC = CRC_TABLE[0xA3 XOR 0xB5] = CRC_TABLE[0x16] = 0x62
PEC = CRC_TABLE[0x62 XOR 0x00] = CRC_TABLE[0x62] = 0x29
PEC = CRC_TABLE[0x29 XOR 0x30] = CRC_TABLE[0x19] = 0x4F
```

两种方法结果一致：**PEC = 0x4F**。

> **提示**: 实际设备返回的数据中，PEC 字节紧随最后一个数据字节之后。本例中，设备在总线上发送 `0x00 0x30 0x4F`（数据低 + 数据高 + PEC），主机收到后对前两个数据字节连同地址和命令重新计算 CRC，比对是否等于 0x4F。

## 6.4 带 PEC 的事务时序

PEC 字节插入在事务的最后一个数据字节之后、STOP 条件之前。不同事务类型的 PEC 时序如下。

### 6.4.1 PEC Write Word 时序

```
  S  Address+W  A  Command  A  Data_L  A  Data_H  A  PEC  A  P
  |___________|____|________|____|______|____|______|____|____|____|__|
      Host              Host              Host              Host
                                                         Slave
```

- 主机发送所有数据字节后，追加一个 PEC 字节
- 从设备接收 PEC 后进行校验
- 如果校验通过，从设备执行写操作
- 如果校验失败，从设备忽略本次写操作，不修改内部寄存器

> **注意**: 对写操作，PEC 校验在**执行写动作之前**完成。校验失败意味着写入不会生效。

### 6.4.2 PEC Read Word 时序

```
  S  Address+W  A  Command  Sr  Address+R  A  Data_L  A  Data_H  A  PEC  N  P
  |___________|____|________|____|__________|____|______|____|______|____|____|__|__|
      Host              Host       Host                Slave         Slave
```

- 主机在读操作时，需要**多读一个字节**来获取 PEC
- PEC 由从设备计算并发送
- 主机收到 PEC 后，对所有字节重新计算 CRC 并比对
- 主机收到 PEC 字节后，发送 NACK 表示传输结束

> **注意**: 启用 PEC 后，主机的读操作必须多读一字节。如果主机按无 PEC 的长度读取，会将 PEC 字节误认为数据，导致数据解析错误。

### 6.4.3 PEC 与事务类型的关系

| 事务类型 | PEC 位置 | PEC 由谁生成 | PEC 由谁校验 |
|----------|---------|-------------|-------------|
| Send Byte + PEC | 紧随 STOP 前 | 主机 | 从设备 |
| Write Byte + PEC | Data 后 | 主机 | 从设备 |
| Write Word + PEC | Data_H 后 | 主机 | 从设备 |
| Read Byte + PEC | Data 后 | 从设备 | 主机 |
| Read Word + PEC | Data_H 后 | 从设备 | 主机 |
| Block Write + PEC | Block 后 | 主机 | 从设备 |
| Block Read + PEC | Block 后 | 从设备 | 主机 |

> **提示**: 简单的记忆规则——**发送数据的一方生成 PEC，接收数据的一方校验 PEC**。对写操作，主机发送数据，主机生成 PEC，从设备校验；对读操作，从设备发送数据，从设备生成 PEC，主机校验。

## 6.5 检测设备是否支持 PEC

并非所有 PMBus 设备都支持 PEC。主机在启用 PEC 之前，应先检测设备的 PEC 能力。

### 6.5.1 CAPABILITY 命令

`CAPABILITY (0x19)` 命令返回一个字节，其中 Bit 7 指示 PEC 支持：

| 位 | 名称 | 说明 |
|----|------|------|
| Bit 7 | PEC Support | 1 = 支持 PEC，0 = 不支持 |
| Bit 6 | SMBALERT# | 1 = 支持 SMBALERT#，0 = 不支持 |
| Bit 5:4 | Max Bus Speed | 00 = 10 kHz, 01 = 100 kHz, 10 = 400 kHz, 11 = reserved |
| Bit 3:0 | Reserved | 保留 |

主机读取 `CAPABILITY` 后，检查 Bit 7：

- Bit 7 = 1：设备支持 PEC，主机可以启用
- Bit 7 = 0：设备不支持 PEC，主机不应发送 PEC 字节

### 6.5.2 QUERY 命令

`QUERY (0x9F)` 命令用于查询设备能力。返回值中 Bit 7 同样表示 PEC 支持：

- Bit 7 = 1：支持 PEC
- Bit 7 = 0：不支持 PEC

`QUERY` 命令同时提供其他能力信息（如是否支持特定命令），但其 PEC 能力位与 `CAPABILITY` 一致。

> **提示**: 在实际系统中，建议优先使用 `CAPABILITY` 命令检测 PEC 支持，因为它除了 PEC 外还提供总线速率和 SMBALERT# 信息，一次读取即可获取多项能力。

## 6.6 PEC 校验失败的处理

PEC 是纯检错机制，不具备纠错能力。检测到 PEC 错误后，应采取以下策略：

### 6.6.1 基本处理原则

1. **丢弃数据**：校验失败的数据字节不应被使用
2. **不修改配置**：对写操作，PEC 失败时从设备不应更新任何配置寄存器或 NVM
3. **记录错误**：记录 PEC 失败次数，用于统计总线质量
4. **重新尝试**：重试同一事务

### 6.6.2 重试策略建议

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 立即重试 | 失败后立即重发同一事务 | 偶发噪声（最常见） |
| 有限重试 | 最多重试 N 次（建议 2~3 次），全部失败后报错 | 一般应用 |
| 延迟重试 | 失败后等待一段时间再重试 | 总线拥塞或设备繁忙 |
| 指数退避 | 每次重试间隔加倍 | 多设备共享总线 |

> **提示**: 应避免将偶发总线噪声误判为永久故障。PEC 失败不一定意味着设备损坏或接线错误，可能只是一次瞬态干扰。建议设置合理的重试次数阈值（如连续 10 次 PEC 失败后再上报故障），同时记录 PEC 错误计数器用于后续分析。

### 6.6.3 从设备端行为

符合 PMBus 规范的设备在 PEC 校验失败时：

- **写操作**：不执行命令，不修改任何寄存器或 NVM，可以设置 `STATUS_CML` 中的通信错误标志位（参见第 8 章）
- **读操作**：PEC 错误由主机端检测，从设备已正常发送数据

## 6.7 不支持 PEC 的设备上发送 PEC 的后果

如果主机向不支持 PEC 的设备发送带 PEC 的事务，会产生以下后果：

| 操作类型 | 后果 |
|----------|------|
| Write + PEC | 从设备将 PEC 字节当作数据写入，导致数据错误或命令码错误 |
| Read + PEC | 从设备按正常长度返回数据，主机多读一字节，读到无效数据 |

**具体风险：**

1. **Write Byte + PEC**：从设备将 PEC 字节当作第 2 个数据字节。如果命令不支持第 2 个字节，从设备可能忽略或产生未定义行为。
2. **Write Word + PEC**：从设备将 PEC 字节当作 Block 数据的第 3 个字节，可能覆盖后续内存或被忽略。
3. **Read Word + PEC**：主机尝试多读一个字节（获取 PEC），但从设备已释放总线，主机读到 0xFF 或总线噪声。

> **警告**: 在启用 PEC 之前，**必须**通过 `CAPABILITY` 命令确认设备支持 PEC。向不支持 PEC 的设备发送 PEC 字节可能导致命令执行错误或通信异常。设备是否接受无 PEC 事务的能力也应在接口文档中明确说明。

## 6.8 常见实现错误

实际系统集成中，PEC 相关的 Bug 是 PMBus 通信问题的常见根源。以下是高频错误：

### 6.8.1 遗漏地址字节

**错误**：PEC 计算中只包含命令码和数据，未包含地址字节。

```
错误: PEC = CRC8([Command, Data1, Data2])    ← 遗漏地址
正确: PEC = CRC8([Address+W, Command, Address+R, Data1, Data2])
```

### 6.8.2 遗漏 REPEATED START 后的地址

**错误**：读操作中只计算 Write 阶段的地址，遗漏 Read 阶段的地址。

```
错误: PEC = CRC8([Address+W, Command, Data1, Data2])        ← 遗漏 Address+R
正确: PEC = CRC8([Address+W, Command, Address+R, Data1, Data2])
```

### 6.8.3 字节序错误

**错误**：PEC 计算中数据字节的顺序与总线传输顺序不一致。

PMBus 的数据传输顺序为低字节在前（Little-Endian），PEC 计算必须与总线传输的实际顺序一致：

```
正确: PEC = CRC8([..., Data_Low, Data_High])    ← 与总线上传输的顺序一致
错误: PEC = CRC8([..., Data_High, Data_Low])    ← 顺序反了
```

### 6.8.4 R/W# 位错误

**错误**：地址字节中 R/W# 位的取值不正确。

```
Write 阶段: Address << 1 | 0 = 0xB4    (W=0)
Read 阶段:  Address << 1 | 1 = 0xB5    (R=1)
```

某些实现错误地将读操作的地址也设为 Write 位（0xB4），导致 PEC 计算结果错误。

### 6.8.5 多项式或初始值错误

**错误**：使用了错误的 CRC-8 参数。

| 常见错误 | 说明 |
|----------|------|
| 使用 0x31 多项式 | 这是 Dallas/Maxim CRC-8，非 SMBus 标准 |
| 初始值用 0xFF | 这是 CRC-8-CCITT，非 SMBus 标准 |
| 启用了输入/输出反射 | SMBus PEC 不使用反射 |

## 6.9 设计建议总结

针对 Omnion Power 数字电源模块的 PMBus 接口，PEC 的设计建议：

| 项目 | 建议 |
|------|------|
| PEC 支持 | 设备应支持 PEC（SMBus 规范要求） |
| PEC 是否强制 | 否，应允许主机选择是否使用 PEC |
| 主机检测方式 | 通过 `CAPABILITY` 命令检测 |
| 校验失败处理 | 丢弃数据、重试、记录错误计数 |
| 查表法 vs 直接计算法 | 推荐 256 字节查表法（固件实现更高效） |
| 错误计数策略 | 避免将偶发噪声误判为永久故障 |

> **提示**: Omnion Power 数字电源产品支持 PEC。PEC 作为可选功能，由主机决定是否启用。设备在收到带 PEC 的事务时，会校验 PEC 并根据结果决定是否执行命令。主机端的 PEC 计算与验证 Python 实现参见第 16 章。
