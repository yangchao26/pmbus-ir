# 第 11 章 设备识别与信息命令

> 主机在首次连接 PMBus 电源模块时，需要确认设备的协议兼容性、功能能力和身份信息。本章讲解 PMBus 标准中用于设备识别的命令，包括协议版本查询（PMBUS_REVISION）、功能能力位域解析（CAPABILITY）、制造商信息字符串读取（MFR 系列命令）、厂商自定义命令空间概述（MFR_SPECIFIC），以及设备能力查询命令（QUERY）。掌握这些命令是完成系统初始化和设备清单（Inventory）管理的基础。

---

## 11.1 PMBUS_REVISION (0x98)：协议版本查询

`PMBUS_REVISION` 是 PMBus 规范定义的必选命令（Mandatory），所有合规设备必须支持。主机通过该命令获取设备所实现的 PMBus 规范版本。

### 命令属性

| 属性 | 值 |
|------|-----|
| 命令码 | 0x98 |
| 访问类型 | 只读 |
| 传输类型 | Read Byte |
| 数据格式 | 8-bit 位域 |

### 数据格式

返回单字节，分为两个独立的修订版本字段：

| 位 | [7:5] | [4] | [3:0] |
|----|-------|-----|-------|
| 功能 | Part I 修订版本 | 保留 | Part II 修订版本 |

- **Bits [7:5]**：PMBus Part I（传输层协议）的修订版本号
- **Bit [4]**：保留位
- **Bits [3:0]**：PMBus Part II（命令集）的修订版本号

### 版本号编码

PMBus 规范定义了以下版本编码：

| PMBus 版本 | Part I 编码 (Bits[7:5]) | Part II 编码 (Bits[3:0]) | 合并值 |
|-----------|----------------------|------------------------|--------|
| 1.0 | 000 | 0000 | 0x00 |
| 1.1 | 001 | 0001 | 0x12 |
| 1.2 | 010 | 0010 | 0x22 |
| 1.3 | 011 | 0011 | 0x33 |

> **提示**: 版本编码的设计使得两个半字节各自表示一个十进制版本号。Bits[7:5] 和 Bits[3:0] 的值直接对应 x.y 中的 x 和 y。

### Omnion Power 模块典型值

Omnion Power 数字电源模块通常返回 **0x22**，表示支持 PMBus 1.2 规范（Part I = 1.2, Part II = 1.2）。

### 主机使用建议

读取 PMBUS_REVISION 是设备发现流程的第一步。主机应根据返回值决定：

1. **是否兼容**：确认设备版本在主机支持的版本范围内
2. **功能范围**：高版本规范包含更多命令和特性，主机可据此选择可用的命令子集
3. **数据格式**：PMBus 1.3 新增了一些数据格式特性，低版本设备不支持

> **注意**: PMBus 规范要求向后兼容。即 1.3 版本的命令集中，1.2 版本已定义的命令行为不变。但 1.2 设备不支持 1.3 新增的命令。

## 11.2 CAPABILITY (0x19)：功能能力查询

`CAPABILITY` 命令返回一个 8-bit 位域，指示设备支持的关键总线功能。主机在系统初始化时应读取该命令，以确定设备的通信能力，并据此配置正确的通信参数。

### 命令属性

| 属性 | 值 |
|------|-----|
| 命令码 | 0x19 |
| 访问类型 | 只读 |
| 传输类型 | Read Byte |
| 数据格式 | 8-bit 位域 |

### 位域定义

| 位 | 名称 | 说明 |
|----|------|------|
| 7 | PEC 支持 | 1 = 设备支持包错误校验（PEC），0 = 不支持 |
| 6 | 保留 | 保留位，始终为 0 |
| 5 | SMBALERT 支持 | 1 = 设备支持 SMBALERT 响应协议，0 = 不支持 |
| 4 | SMBus 警报 | 1 = 设备支持 SMBus 警报功能，0 = 不支持 |
| [3:2] | 最大总线速率 | 指示设备支持的最高 SMBus/PMBus 时钟频率 |
| 1 | 保留 | 保留位，始终为 0 |
| 0 | 保留 | 保留位，始终为 0 |

### Bit 7：PEC 支持

该位指示设备是否在所有总线事务中支持包错误校验。

| 值 | 含义 |
|----|------|
| 1 | 设备支持 PEC。主机发送的 PEC 会被设备校验；设备响应中包含 PEC |
| 0 | 设备不支持 PEC |

当设备支持 PEC 时，主机应在所有事务中发送和校验 PEC 字节。PEC 的计算方法详见第 6 章。

> **警告**: 在不支持 PEC 的设备上发送 PEC 字节会导致通信错误，设备将 NACK 该事务。

### Bit 5：SMBALERT 支持

该位指示设备是否支持 SMBALERT 响应协议，即设备是否能在检测到故障/警告条件时主动拉低 SMBALERT# 信号通知主机。

| 值 | 含义 |
|----|------|
| 1 | 设备支持 SMBALERT 响应协议（详见第 7 章） |
| 0 | 设备不支持 SMBALERT，主机必须使用轮询方式检测故障 |

### Bit 4：SMBus 警报

该位指示设备是否支持 SMBus Alert 功能（对应 SMBus 规范中的 Alert 机制）。

### Bits [3:2]：最大总线速率

这两位编码指示设备支持的最高总线时钟频率：

| Bits [3:2] | 最高频率 | 说明 |
|-----------|---------|------|
| 00 | 10 kHz | 最低速率模式 |
| 01 | 100 kHz | 标准模式 |
| 10 | 400 kHz | 快速模式 |
| 11 | 保留 | 保留值 |

> **提示**: 选择总线速率时应考虑总线电容和上拉电阻值。较长的总线走线或多设备系统可能无法稳定运行在 400 kHz。总线速率和物理层设计详见第 2 章。

### Omnion Power 模块典型值

Omnion Power 数字电源模块的 CAPABILITY 典型值为 **0xB0**：

| 位域 | 值 | 含义 |
|------|-----|------|
| Bit 7 (PEC) | 1 | 支持 PEC |
| Bit 6 | 0 | 保留 |
| Bit 5 (SMBALERT) | 1 | 支持 SMBALERT |
| Bit 4 | 1 | 支持 SMBus 警报 |
| Bits [3:2] (速率) | 00 | 最高 10 kHz（注：设备实际支持 100 kHz 和 400 kHz） |
| Bits [1:0] | 0 | 保留 |

> **注意**: CAPABILITY 中总线速率字段的编码值与设备实际支持的速率可能不完全一致，设备实际支持的总线速率应以具体产品 Datasheet 为准。

### 主机使用建议

读取 CAPABILITY 后，主机应执行以下配置：

1. **PEC 配置**：根据 Bit 7 决定是否启用 PEC 计算和校验
2. **SMBALERT 配置**：根据 Bit 5 决定是否初始化 SMBALERT 中断处理（详见第 7 章）
3. **总线速率选择**：以 Bits [3:2] 作为上限参考，结合实际总线条件选择合适的速率

## 11.3 制造商信息命令

PMBus 规范定义了一组以 `MFR_` 为前缀的命令，用于读取设备的身份标识信息。这些命令返回 ASCII 字符串，使用 **Block Read** 传输类型读取（详见第 4 章第 4.4 节）。Block Read 的第一个字节为数据长度 N，后续 N 个字节为实际数据。

### 命令汇总

| 命令 | 命令码 | 传输类型 | 数据格式 | 说明 |
|------|--------|---------|---------|------|
| MFR_ID | 0x99 | Read Block | 8-bit ASCII 字符串 | 厂商标识 |
| MFR_MODEL | 0x9A | Read Block | 8-bit ASCII 字符串 | 产品型号 |
| MFR_REVISION | 0x9B | Read Block | 8-bit ASCII 字符串 | 硬件/固件版本 |
| MFR_LOCATION | 0x9C | Read Block | 8-bit ASCII 字符串 | 制造地点 |
| MFR_DATE | 0x9D | Read Block | 8-bit ASCII 字符串 | 制造日期 |
| MFR_SERIAL | 0x9E | Read Block | 8-bit ASCII 字符串 | 产品序列号 |

### Block Read 读取流程

所有 MFR 信息命令使用 Block Read 传输类型。读取流程如下：

```
主机发送: [START] [从地址+W] [命令码] [STOP]
设备响应: [START] [从地址+R] [长度 N] [数据 1] [数据 2] ... [数据 N] [PEC] [STOP]
```

主机首先发送从地址 + 写方向 + 命令码，然后通过 REPEATED START 切换为读方向，设备返回一个长度字节 N 和 N 个数据字节。如果设备支持 PEC，则在最后一个数据字节之后还有一个 PEC 字节。

### 11.3.1 MFR_ID (0x99)：厂商标识

返回制造商的唯一标识字符串。

| 属性 | 值 |
|------|-----|
| 命令码 | 0x99 |
| 数据格式 | Block Read（8-bit ASCII） |
| Omnion Power 典型值 | "OMPW"（4 字节 + 1 长度字节） |

Omnion Power 模块的 MFR_ID 固定为 **"OMPW"**，这是 OmniOn Power 在 PMBus 命名空间中的厂商代码。主机可通过该值快速识别总线上的设备是否为 Omnion Power 产品。

### 11.3.2 MFR_MODEL (0x9A)：产品型号

返回具体的产品型号字符串。

| 属性 | 值 |
|------|-----|
| 命令码 | 0x9A |
| 数据格式 | Block Read（8-bit ASCII） |
| 典型长度 | 17 字节 + 1 长度字节 |

该字符串标识具体的产品型号（如 QODN167A0B 及其完整后缀），每台设备的型号字符串相同。主机可利用此命令在多设备系统中识别每个模块的型号。

### 11.3.3 MFR_REVISION (0x9B)：硬件/固件版本

返回设备的硬件或固件版本信息。

| 属性 | 值 |
|------|-----|
| 命令码 | 0x9B |
| 数据格式 | Block Read（8-bit ASCII） |
| 典型长度 | 7 字节 + 1 长度字节 |

版本字符串的格式和含义由厂商定义。对于固件版本，Omnion Power 还提供了独立的 `MFR_FW_REV` 命令（见第 11.4 节），以数值方式返回固件版本，便于程序化比较。

### 11.3.4 MFR_LOCATION (0x9C)：制造地点

返回设备的制造地点信息。

| 属性 | 值 |
|------|-----|
| 命令码 | 0x9C |
| 数据格式 | Block Read（8-bit ASCII） |
| 典型长度 | 11 字节 + 1 长度字节 |

该信息可用于质量追溯和供应链管理。部分应用场景中，MFR_LOCATION 可通过 `MFR_MODULE_DATE_LOC_SN`（0xF0）命令统一写入（受写保护控制）。

### 11.3.5 MFR_DATE (0x9D)：制造日期

返回设备的制造日期字符串。

| 属性 | 值 |
|------|-----|
| 命令码 | 0x9D |
| 数据格式 | Block Read（8-bit ASCII） |
| 典型长度 | 5 字节 + 1 长度字节 |

日期格式通常为 "YYYY-MM" 或类似的可读格式，由厂商定义。

### 11.3.6 MFR_SERIAL (0x9E)：产品序列号

返回产品的唯一序列号。

| 属性 | 值 |
|------|-----|
| 命令码 | 0x9E |
| 数据格式 | Block Read（8-bit ASCII） |
| 典型长度 | 17 字节 + 1 长度字节 |

序列号是每台设备的唯一标识，可用于库存管理、保修跟踪和故障追溯。与 MFR_ID 和 MFR_MODEL 一起，这三个命令可构成设备的完整身份标识。

### 设备清单（Inventory）应用

在数据中心和服务器系统中，主机通常在启动时通过读取以下命令构建设备清单：

```
PMBUS_REVISION → 确认协议兼容性
CAPABILITY     → 确认功能能力
MFR_ID         → 识别厂商
MFR_MODEL      → 识别型号
MFR_SERIAL     → 唯一标识
MFR_REVISION   → 版本信息
MFR_DATE       → 制造日期
MFR_LOCATION   → 制造地点
```

该清单可用于资产管理、固件升级决策和系统诊断。编程实现示例详见第 16 章。

## 11.4 厂商自定义命令概述

PMBus 规范在命令空间中为厂商预留了专有命令区域，用于实现标准命令未覆盖的功能。

### MFR_SPECIFIC 命令空间

| 地址范围 | 用途 |
|---------|------|
| 0xC0 ~ 0xFF | 厂商自定义命令（Manufacturer Specific） |

其中 **0xC4 ~ 0xFD** 为厂商专有命令的核心区域。这些命令的名称、数据格式和功能完全由厂商定义，不同厂商的设备之间不兼容。

### Omnion Power 常见 MFR 命令

以下是 Omnion Power 数字电源模块中常见的厂商自定义命令：

| 命令 | 命令码 | 传输类型 | 数据格式 | 说明 |
|------|--------|---------|---------|------|
| MFR_DEVICE_TYPE | 0xD0 | R/W Word | 16-bit 自定义 | 写保护控制（WPE 位）及模块名称编码 |
| MFR_FW_REV | 0xDB | Read Word | 16-bit 无符号 | 固件版本（4 位十六进制：Major.Minor.BuildHigh.BuildLow） |
| MFR_PGOOD_POLARITY | 0xE2 | R/W Byte | Bit field | PGOOD 信号极性选择 |
| MFR_MODULE_DATE_LOC_SN | 0xF0 | R/W Block | 8-bit ASCII | 模块日期、地点和序列号（12 字节 Block） |

### MFR_DEVICE_TYPE (0xD0)：写保护控制

该命令同时承担写保护控制和模块名称编码两项功能。

| 属性 | 值 |
|------|-----|
| 命令码 | 0xD0 |
| 传输类型 | R/W Word |
| 数据格式 | 16-bit 自定义位域 |

位域定义：

| 字节 | 位 7 | 位 6 | 位 5 | 位 4 | 位 3 | 位 2 | 位 1 | 位 0 |
|------|------|------|------|------|------|------|------|------|
| 高字节 | 保留 | Module Name[11:7] |
| 低字节 | Module Name[6:2] | WPE | 保留 |

- **WPE（Bit 1）**：Write Protect Enable
  - 0 = 写保护未激活，所有可写命令可正常执行
  - 1 = 写保护激活，受保护的命令将被静默忽略（不产生通信错误）
- **Module Name [11:2]**：12-bit 模块名称编码，用于标识产品型号
- **默认值**：WPE = 1（写保护默认启用），需先解除写保护才能修改受保护参数

> **提示**: 修改 WPE 位的设置后，需通过 `STORE_DEFAULT_ALL`（详见第 10 章）保存到非易失性存储器才能掉电保持。

### MFR_FW_REV (0xDB)：固件版本

以数值格式返回模块的固件版本，便于程序化读取和比较。

| 属性 | 值 |
|------|-----|
| 命令码 | 0xDB |
| 传输类型 | Read Word |
| 数据格式 | 16-bit 无符号整数 |

格式：0x**Mj.Mn.Bh.Bl**

| 半字节 | 含义 |
|--------|------|
| 高半字节（位 [15:12]） | Major revision（主版本号） |
| 位 [11:8] | Minor revision（次版本号） |
| 位 [7:4] | Build high（构建号高位） |
| 位 [3:0] | Build low（构建号低位） |

例如返回值为 0x1218，表示固件版本为 **1.2.18**。

### MFR_PGOOD_POLARITY (0xE2)：PGOOD 极性

配置 Power Good 信号的逻辑极性。

| 属性 | 值 |
|------|-----|
| 命令码 | 0xE2 |
| 传输类型 | R/W Byte |
| 数据格式 | Bit field |

| 位 | 功能 | 值 |
|----|------|-----|
| 0 | PGOOD 逻辑 | 0 = 负逻辑（PG 断言时引脚为低）；1 = 正逻辑（PG 断言时引脚为高） |
| [7:1] | 保留 | 始终为 0 |

### MFR_MODULE_DATE_LOC_SN (0xF0)：模块信息写入

该命令允许主机通过一条 Block Write 操作同时写入模块的制造日期、地点和序列号信息，受 MFR_DEVICE_TYPE 写保护控制。

| 属性 | 值 |
|------|-----|
| 命令码 | 0xF0 |
| 传输类型 | R/W Block |
| 数据长度 | 12 字节 |

> **注意**: 厂商自定义命令的具体行为和数据格式因产品而异，完整列表参见附录 A。使用自定义命令前应参考具体产品 Datasheet。

## 11.5 QUERY (0x9F)：查询设备能力

`QUERY` 命令是一种特殊的事务类型——Receive Byte（无命令码的单字节读取）。主机通过向设备的从地址发送读请求来执行 QUERY，设备返回一个包含能力信息的字节。

### 命令属性

| 属性 | 值 |
|------|-----|
| 命令码 | 0x9F（概念上存在，实际不作为命令码发送） |
| 传输类型 | Receive Byte |
| 数据格式 | 8-bit 位域 |

### 事务流程

QUERY 使用 **Receive Byte** 传输类型，不发送命令码：

```
主机发送: [START] [从地址+R] [数据字节] [PEC] [STOP]
```

> **提示**: Receive Byte 与 Read Byte 的区别在于——Read Byte 需要先发送命令码（写方向），再通过 REPEATED START 读取数据；而 Receive Byte 直接以读方向发起事务，不发送命令码。详见第 4 章第 4.5 节。

### 返回值位域

| 位 | 名称 | 说明 |
|----|------|------|
| 7 | PEC 支持 | 1 = 设备支持 PEC |
| [6:0] | 厂商自定义 | 厂商自定义的能力标志 |

### 返回值含义

- **Bit 7 = 1**：设备支持 PEC。该标志与 CAPABILITY 命令的 Bit 7 含义一致，为主机提供了一种快速检测 PEC 支持的方式
- **Bits [6:0]**：保留给厂商定义额外能力标志。具体含义因产品而异，参见具体产品 Datasheet

### 与 CAPABILITY 的关系

QUERY 和 CAPABILITY 都能指示设备是否支持 PEC，两者的区别在于：

| 特性 | QUERY | CAPABILITY |
|------|-------|------------|
| 传输类型 | Receive Byte | Read Byte |
| 是否需要命令码 | 不需要 | 需要（0x19） |
| PEC 标志位 | Bit 7 | Bit 7 |
| 额外功能标志 | 仅 PEC + 厂商自定义 | SMBALERT、总线速率等 |
| 推荐使用场景 | 快速 PEC 检测 | 完整能力评估 |

> **建议**: 在系统初始化时，应优先使用 CAPABILITY 命令获取完整的设备能力信息。QUERY 可作为快速 PEC 检测的备用手段。
