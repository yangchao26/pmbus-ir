# 第 15 章 调试与故障排查

本章提供 PMBus 调试与故障排查的系统方法，覆盖从物理层总线问题到数据格式异常的常见场景。每个问题均按"现象 → 可能原因 → 排查步骤"的格式组织，并给出示波器与逻辑分析仪的使用建议以及完整的互操作性检查清单，帮助工程师快速定位和解决 PMBus 集成问题。

---

## 15.1 常见通信问题与解决方案

### 15.1.1 NACK 无响应

**现象**

主机发送地址字节后，从设备始终返回 NACK（非确认），所有命令均无法访问设备。

**可能原因**

| 序号 | 可能原因 | 排查要点 |
|------|----------|----------|
| 1 | 设备地址错误 | 地址配置电阻/引脚未正确设置 |
| 2 | 设备未就绪 / 未上电 | VIN 低于启动阈值，通信尚未使能 |
| 3 | 总线被其他从设备拉低 | 多设备场景下总线冲突 |
| 4 | 上拉电阻缺失或阻值过大 | SDA/SCL 无法上升到 VIH 电平 |
| 5 | 主机 I²C 控制器速率过高 | 设备不支持当前总线速率 |
| 6 | 设备处于通信不可用时段 | 启动期间或停止操作后的保护窗口 |

**排查步骤**

1. **确认上电时序**：检查 VIN 是否已超过模块启动电压，且通信使能条件已满足（详见第 13 章）。模块上电后通常有数毫秒的通信不可用窗口。

2. **确认设备地址**：对照 Datasheet 中的地址配置说明，核实地址设定电阻或引脚配置。Omnion Power 模块的默认地址和配置方式参见具体产品 Datasheet。

3. **地址扫描**：以低速（100 kHz）逐地址扫描总线，确认设备实际响应的地址。多设备系统中尤其要注意地址是否冲突。

4. **检查上拉电阻**：用示波器确认 SDA/SCL 在空闲状态下能被可靠拉高至接近 VDD。推荐上拉电阻值参见第 2 章。

5. **降低总线速率**：将主机控制器切换到 100 kHz 标准模式，排除高速模式下信号完整性问题。

6. **多设备隔离**：如果总线上有多个从设备，断开其他设备，逐一确认每个设备的地址和响应。

> **提示**: 首次联调时建议从低速、单设备、简单读取（如 `PMBUS_REVISION (0x98)`）开始，逐步增加复杂度。完整的 Bring-up 流程参见第 14 章。

### 15.1.2 Bus Stuck / SDA 被拉低

**现象**

主机无法发起任何事务，SCL 或 SDA 信号被持续拉低，总线处于挂死状态。

**可能原因**

| 序号 | 可能原因 | 排查要点 |
|------|----------|----------|
| 1 | 从设备状态机卡死 | 从设备在中途事务中被复位或超时 |
| 2 | 主机控制器异常退出事务 | 主机在 Read 操作期间被中断 |
| 3 | 从设备时钟拉伸超时 | 从设备内部处理时间过长，持续拉低 SCL |
| 4 | 噪声导致状态机不同步 | 信号完整性差，毛刺触发错误状态 |
| 5 | 设备 firmware 卡在服务中 | NVM 操作或中断处理期间通信异常 |
| 6 | 热插拔或电源时序异常 | Bus buffer 隔离或设备上电顺序不当 |

**总线恢复步骤**

当总线挂死时，按以下步骤执行恢复（详见第 2 章中 SMBus 总线恢复机制）：

```text
步骤 1: 停止当前 SMBus/I²C controller 的所有待处理事务
步骤 2: 将 SCL 和 SDA 切换为 GPIO 模式
        （或使用控制器内置的 bus recovery 功能）
步骤 3: 确认 SCL 可以被释放为高电平
        —— 如果 SCL 始终被拉低，需要检查硬件连接或隔离故障设备
步骤 4: 主机驱动 SCL 产生最多 9 个时钟脉冲，
        逐步让从设备完成当前字节传输并释放 SDA
步骤 5: 在 SDA 释放后（检测到 SDA = High），
        主机生成 STOP 条件（SCL 高时 SDA 上升沿）
步骤 6: 重新初始化 SMBus/I²C controller
步骤 7: 执行地址扫描或读取关键 STATUS 寄存器，
        确认设备通信恢复正常
```

> **提示**: 如果 9 个 SCL 脉冲后 SDA 仍未释放，可能需要物理断开故障设备或复位其电源域。在多设备总线中，建议使用支持总线恢复的 Bus Buffer（如 TCA4307 / TCA4311A）。

**恢复后验证**

恢复后建议执行以下操作确认系统状态：

1. 读取 `STATUS_BYTE (0x78)` 和 `STATUS_CML (0x7E)`，检查是否有通信故障标志（详见第 8 章和附录 D）
2. 确认 `READ_VOUT (0x8B)` 等遥测数据读数合理（详见第 12 章）
3. 如果设备支持 SMBALERT，检查 SMBALERT# 是否处于无效状态

**预防措施**

- 主机端驱动必须实现超时检测，避免无限等待（参见第 14 章）
- 将 bus recovery 作为独立的状态机状态，不在普通重试中无限循环
- 对多设备总线，区分总线级错误（bus-level error）和设备级错误（device-level error），避免误判所有电源模块故障

### 15.1.3 PEC 校验失败

**现象**

启用了 PEC 后，从设备返回 NACK 或在 `STATUS_CML` 中报告 `PEC_FAILED`；主机端 CRC 校验结果与收到的 PEC 字节不匹配。

**可能原因**

| 序号 | 可能原因 | 排查要点 |
|------|----------|----------|
| 1 | PEC 计算范围错误 | 漏算或多算了某些字节 |
| 2 | CRC 多项式实现错误 | 使用了错误的初始值或多项式 |
| 3 | 读取事务中 PEC 字节未正确接收 | 主机多读一字节的时序处理有误 |
| 4 | 时序问题导致字节丢失 | Clock Stretching 或总线速率不匹配 |
| 5 | 设备不支持 PEC 但主机发送了 PEC | 设备将 PEC 字节当作数据处理 |
| 6 | 写操作 PEC 在错误位置插入 | 写事务中 PEC 应紧跟最后一个数据字节 |

**排查步骤**

1. **确认设备是否支持 PEC**：通过 `QUERY (0x9F)` 命令（Bit 7 = 1 表示支持 PEC）或 `CAPABILITY (0x19)` 命令确认（详见第 6 章）。

2. **验证 CRC 计算范围**：PEC 的计算输入包括地址字节（含 R/W# 位）+ 命令字节 + 所有数据字节，不包含 START、STOP、ACK 信号。使用已知的 Read Word 命令（如 `PMBUS_REVISION (0x98)`）作为验证用例。

3. **检查多项式和初始值**：PMBus 使用 CRC-8 多项式 x^8 + x^2 + x + 1（0x07），初始值为 0（详见第 6 章）。确保实现与规范一致。

4. **检查读事务中的 PEC 接收时序**：带 PEC 的 Read Word 事务中，主机在读取完 2 个数据字节后，需要额外读取 1 个字节获取 PEC。在最后一个字节上发 NACK 而非 ACK。

5. **检查写事务中的 PEC 发送时序**：带 PEC 的 Write Word 事务中，主机在发送完最后一个数据字节后紧跟发送 PEC 字节，然后发 STOP。

> **提示**: 如果设备不支持 PEC，主机发送 PEC 字节后设备通常将其视为额外的数据字节，可能导致命令解析错误并设置 `STATUS_CML`。对于不支持 PEC 的设备，建议关闭 PEC 功能。

### 15.1.4 时钟拉伸超时

**现象**

事务进行中主机报告超时错误，SCL 在较长一段时间内被从设备拉低；多次重试后仍然超时。

**可能原因**

| 序号 | 可能原因 | 排查要点 |
|------|----------|----------|
| 1 | 从设备正在准备 Read Word 数据 | ADC 采样或数据格式转换耗时 |
| 2 | 从设备正在执行 NVM Store/Restore | Flash 写入/读取耗时较长 |
| 3 | Fault 发生后状态寄存器同步延迟 | 多个 STATUS 寄存器需要更新 |
| 4 | 固件服务中断处理中 | 中断服务程序占用 SCL |
| 5 | 主机端超时设置过短 | 未给从设备留够处理时间 |
| 6 | SMBus TTIMEOUT,MIN 不匹配 | 主机与从设备的超时阈值不一致 |

**排查步骤**

1. **确认是否为特定命令的超时**：逐命令测试，定位是所有命令都超时还是特定命令（如 `STORE_DEFAULT_ALL`、`STORE_USER_ALL`）超时。NVM 操作通常需要更长完成时间。

2. **检查 SMBus 超时参数**：SMBus 规范要求 TTIMEOUT,MIN = 25 ms，TTIMEOUT,MAX = 35 ms（详见第 2 章）。确保主机控制器的超时设置不小于 25 ms。

3. **用示波器观察 SCL 拉低持续时间**：测量从设备拉伸 SCL 的实际时长。如果接近或超过 25 ms，需要评估是正常行为还是从设备异常。

4. **排除 NVM 操作的影响**：NVM Store/Restore 期间通信可能不可用（详见第 10 章）。确保 NVM 操作前后留出足够的等待时间，且输出已关闭。

5. **调整主机超时策略**：
   - 常规命令：超时 25~35 ms
   - NVM 操作：超时 [参见具体产品 Datasheet]（通常为数百毫秒级）
   - 超时后执行有限次重试（建议不超过 3 次）
   - 持续超时应标记设备为离线或降级

> **提示**: 从设备不应将时钟拉伸作为常规限速手段。如果遥测数据准备时间较长，推荐使用 Shadow Register 架构，将实时采样与 PMBus 访问解耦。

### 15.1.5 数据值异常

**现象**

读取的遥测数据明显偏离预期（如 READ_VOUT 读数为负值、READ_IOUT 读数为实际值的数倍或数分之一、温度读数为 0 等）。

**可能原因**

| 序号 | 可能原因 | 排查要点 |
|------|----------|----------|
| 1 | 11-bit Linear 格式解码错误 | 指数 N 或尾数 Y 的提取方式不正确 |
| 2 | 字节序错误 | 高低字节颠倒 |
| 3 | VOUT_MODE 指数 N 未正确应用 | 电压命令使用了错误的指数 |
| 4 | 有符号与无符号混用 | 将有符号值当作无符号值解码 |
| 5 | 写入时编码错误 | Linear 格式编码计算失误 |
| 6 | 设备返回了无效数据 | 设备故障或 ADC 未就绪 |
| 7 | 读取了不支持的命令 | 设备返回 NACK 或默认数据 |

**排查步骤**

**A. 检查字节序**

PMBus 在 I²C 总线上以低字节先传（Little-Endian）的顺序传输多字节数据。例如 Read Word 返回 0xABCD 时：
- 第 1 个字节（先收到的）= 0xCD（低字节）
- 第 2 个字节（后收到的）= 0xAB（高字节）

主机端驱动应将这两个字节重新组合为 `value = (high_byte << 8) | low_byte`。如果字节序颠倒，数据将完全错误。

**B. 验证 11-bit Linear 解码**

11-bit Linear 数据格式中，16-bit 数据的高 5 位为指数 N（Two's Complement），低 11 位为尾数 Y（Two's Complement）。解码公式为：

```
VALUE = Y × 2^N
```

排查解码是否正确的方法：

1. 先确认提取的 N 和 Y 值。例如原始 16-bit 值为 `0xE085`：
   - 高 5 位 = 0xE = 0b11100，作为 5-bit Two's Complement → N = -4
   - 低 11 位 = 0x085 = 0b000010000101，作为 11-bit Two's Complement → Y = 133

2. 验证计算：VALUE = 133 × 2^(-4) = 133 / 16 = 8.3125

3. 与实际测量值（用示波器或 DMM）对比，确认数量级和趋势一致。

> 11-bit Linear 的完整编码/解码方法参见第 5 章，编码/解码快速参考参见附录 B。

**C. 检查 VOUT_MODE 指数 N**

对于电压类命令（`VOUT_COMMAND`、`READ_VOUT` 等），设备通过 `VOUT_MODE (0x20)` 命令返回固定的指数 N。主机在编码/解码电压值时必须使用此指数。

如果写入设备不支持的 VOUT_MODE 值（如写入 VID 模式但设备只支持 ULINEAR16），设备通常会：
- 对数据字节返回 NACK
- 忽略该写入，保持原有 VOUT_MODE 不变
- 设置 `STATUS_CML (0x7E)` 的 Bit 6（`Invalid Or Unsupported Data Received`）

验证方法：写入后重新读取 `VOUT_MODE`，确认其值未发生变化。

**D. 有符号数处理**

11-bit Linear 格式的 N 和 Y 均为 Two's Complement 有符号数。提取时需要正确处理符号扩展：

- 5-bit N 的范围：-16 ~ +15。当高 5 位的最高位为 1 时（即 0b1xxxx），N 为负值，需做符号扩展。
- 11-bit Y 的范围：-1024 ~ +1023。同理。

如果将有符号值误判为无符号，会导致指数或尾数完全错误。

**E. 交叉验证遥测数据**

| 遥测命令 | 验证方法 |
|----------|----------|
| `READ_VIN (0x88)` | 与示波器/DMM 测量的输入电压对比 |
| `READ_VOUT (0x8B)` | 与示波器/DMM 测量的输出电压对比 |
| `READ_IOUT (0x8C)` | 空载时应接近 0，加载负载后应增大 |
| `READ_TEMPERATURE_1 (0x8D)` | 应与环境温度量级一致 |

## 15.2 示波器抓包要点

示波器是 PMBus 调试中最常用的工具，适合观察信号质量和时序参数。

### 15.2.1 基本设置

| 参数 | 建议设置 |
|------|----------|
| 探头类型 | 10x 无源探头，或 1x/10x 可切换探头 |
| 带宽 | ≥ 100 MHz（100 kHz 总线），≥ 400 MHz（400 kHz 总线） |
| 采样率 | ≥ 10× 总线时钟频率 |
| 记录长度 | 足够捕获完整事务（建议 ≥ 10 kpts） |
| 触发源 | SDA 或 SCL |

### 15.2.2 触发设置

**START 条件触发**

START 条件是每个事务的起点，设置 START 条件触发可以稳定捕获完整事务：

- 触发类型：I²C START 或下降沿触发
- 触发条件：SCL = High 时 SDA 出现下降沿
- 大部分示波器内置 I²C 触发/解码功能，可直接选择 "I²C Start" 触发模式

**NACK 触发**

当排查 NACK 问题时，可将触发条件设为 NACK（第 9 个时钟脉冲的 SDA = High）：

- 触发类型：I²C NACK
- 适用于定位哪个地址或哪个数据字节引发了 NACK

**SMBALERT# 触发**

- 触发类型：下降沿触发（SMBALERT# 为低电平有效）
- 配合长记录长度，可以捕获 Alert 前后的一段总线活动

### 15.2.3 关键信号与测量点

推荐至少探测以下信号：

| 信号 | 测量要点 |
|------|----------|
| SCL | 空闲电平、上升/下降时间、时钟频率 |
| SDA | 空闲电平、上升/下降时间、数据建立/保持时间 |
| SMBALERT# | 是否被触发、触发持续时间、恢复时序 |

**关键时序参数测量**

以下参数的测量方法参见第 2 章中的 I²C/SMBus 时序参数定义：

| 参数 | 含义 | 测量要点 |
|------|------|----------|
| tSU;DAT | 数据建立时间 | SDA 在 SCL 上升沿之前稳定的时间 |
| tHD;DAT | 数据保持时间 | SDA 在 SCL 下降沿之后保持的时间 |
| tR / tF | 信号上升/下降时间 | 从 10% 到 90%（或 30% 到 70%）的转换时间 |
| tLOW | SCL 低电平时间 | 包含从设备的时钟拉伸时间 |
| tHIGH | SCL 高电平时间 | |
| tBUF | 总线空闲时间 | STOP 与下一个 START 之间的间隔 |
| tTIMEOUT | 总线超时时间 | SCL/SDA 未活动的时间 |

## 15.3 逻辑分析仪使用建议

逻辑分析仪适合捕获长时间、多通道的协议数据，适合协议级调试和数据验证。

### 15.3.1 I²C/SMBus 解码器配置

| 配置项 | 建议值 |
|--------|--------|
| 协议选择 | I²C / SMBus（大多数逻辑分析仪二选一即可） |
| 信号映射 | SCL → Channel 0, SDA → Channel 1 |
| 采样率 | ≥ 4 MHz（推荐 ≥ 10 MHz） |
| 阈值电压 | 根据总线 VDD 设置（通常 1.5V 或 3.3V） |
| SCL 拉伸支持 | 启用（如解码器支持） |

> **提示**: 如果逻辑分析仪同时解码 I²C 和 SMBus，优先使用 I²C 解码器，因为 PMBus 的基础传输基于 I²C 时序。SMBus 解码器主要用于验证超时等 SMBus 特有的行为。

### 15.3.2 长时间抓包与协议分析

**捕获策略**

| 场景 | 采样率 | 记录深度 | 通道 |
|------|--------|----------|------|
| 单事务分析 | 10 MHz+ | 1 kpts | SCL, SDA |
| 间歇性故障定位 | 4 MHz | 最大 | SCL, SDA, SMBALERT#, GPIO |
| 多设备通信分析 | 4 MHz | 最大 | SCL, SDA |

**协议分析要点**

- **地址解码**：确认事务的目标地址与预期一致
- **命令字节解析**：确认发送的命令码正确
- **数据字节验证**：对照 PMBus 命令的数据格式，确认数据字节数和数据值正确
- **ACK/NACK 位置**：定位 NACK 发生的位置（地址字节、命令字节还是数据字节）
- **START/STOP 位置**：确认 REPEATED START（Sr）和 STOP 条件的正确性（详见第 4 章）

**间歇性问题的捕获方法**

1. 使用逻辑分析仪的触发过滤功能，仅在出现 NACK、STOP 条件异常或 SMBALERT# 下降沿时触发记录。
2. 在触发前后预留足够的预触发（pre-trigger）和后触发（post-trigger）深度，确保捕获到故障前后的上下文。
3. 将抓包数据导出为 CSV 或二进制格式，使用脚本进行批量分析。

## 15.5 分层故障定位方法

PMBus 通信涉及多个协议层次，问题可能出现在物理层、数据链路层或 PMBus 命令层。建议按以下顺序逐层排查。

### 15.5.1 物理层

| 检查方法 | 工具 | 目标 |
|----------|------|------|
| 示波器观察 SDA/SCL 波形 | 示波器 | 确认空闲电平、上升/下降时间、无毛刺 |
| 测量上拉电阻值 | 万用表 | 确认阻值在推荐范围内（详见第 2 章） |
| 检查总线电容 | 示波器（通过上升时间估算） | 确认不超过 400 pF |
| 检查接线和连接器 | 目视检查 | 确认无虚焊、短路、接触不良 |

### 15.5.2 数据链路层（I²C/SMBus）

| 检查方法 | 工具 | 目标 |
|----------|------|------|
| 地址扫描 | 主机驱动 | 确认设备地址正确、总线可用 |
| 单字节读取测试 | 主机驱动 | 读取 `PMBUS_REVISION (0x98)` 验证基本通信 |
| 逻辑分析仪抓包 | 逻辑分析仪 | 确认 START/STOP/ACK/NACK 时序正确 |
| PEC 验证 | 主机驱动 | 对已知命令验证 PEC 计算正确性 |

### 15.5.3 PMBus 命令层

| 检查方法 | 工具 | 目标 |
|----------|------|------|
| 遥测数据合理性 | 主机驱动 + DMM/示波器 | 遥测读数与实际测量值一致 |
| STATUS 寄存器读取 | 主机驱动 | 确认 STATUS 位域与设备状态一致 |
| 控制命令验证 | 主机驱动 + 示波器 | OPERATION / ON_OFF_CONFIG 行为正确 |
| Linear 格式验证 | 主机驱动 | 编码/解码计算与规范一致 |

### 15.5.4 分层排查流程

```text
通信失败
  │
  ├─ 示波器确认 SDA/SCL 波形是否正常？
  │    └─ 否 → 物理层问题（检查上拉电阻、接线、总线电容）
  │
  ├─ 逻辑分析仪确认 START/STOP/ACK 时序是否正确？
  │    └─ 否 → 数据链路层问题（检查主机控制器配置、时序参数）
  │
  ├─ 地址扫描能否发现设备？
  │    └─ 否 → 物理层或地址配置问题
  │
  ├─ 单字节读取（PMBUS_REVISION）是否成功？
  │    └─ 否 → 数据链路层问题（检查速率、时钟拉伸）
  │
  ├─ PEC 是否校验通过？
  │    └─ 否 → PEC 实现问题（检查 CRC 多项式、计算范围）
  │
  ├─ 遥测数据是否合理？
  │    └─ 否 → 数据格式问题（检查 Linear 解码、VOUT_MODE）
  │
  └─ STATUS 寄存器是否有异常标志？
       └─ 是 → 根据 STATUS 位域定位具体故障类型（详见第 8 章）
```

## 15.6 不支持命令和数据写入的处理

在集成开发中，主机可能会发送设备不支持的命令，或向设备写入不支持的数据值。了解设备的预期行为有助于快速区分"正常拒绝"和"真实故障"。

### 15.6.1 不支持的命令

当主机发送设备不支持的命令码时：

- **I²C 层**：设备可能对命令字节返回 NACK
- **PMBus 层**：设备设置 `STATUS_CML (0x7E)` 的 Bit 7（`Invalid Or Unsupported Command Received`）
- **行为**：设备忽略该命令，不会执行任何操作

### 15.6.2 不支持的数据值

当主机向设备发送的命令码正确但数据值不被支持时（例如向只支持 ULINEAR16 模式的设备写入 VID 模式的 `VOUT_MODE`）：

- **I²C 层**：设备可能对数据字节返回 NACK，也可能接受写入
- **PMBus 层**：设备设置 `STATUS_CML (0x7E)` 的 Bit 6（`Invalid Or Unsupported Data Received`）
- **行为**：设备忽略此次写入，寄存器保持原值不变
- **验证方法**：写入后重新读取该寄存器，确认值未变化

> **提示**: 建议在写入关键配置（如 `VOUT_MODE`、`FAULT_LIMIT`、`ON_OFF_CONFIG`）后执行回读验证，确认写入值被设备接受。

### 15.6.3 事务失败的分层解读

| 层次 | 观察到的现象 | 含义 |
|------|------------|------|
| I²C/SMBus 事务层 | NACK 或驱动层超时错误 | 总线级通信失败 |
| PMBus 状态层 | `STATUS_BYTE` / `STATUS_CML` 有异常标志 | 命令或数据被拒绝 |
| 配置寄存器层 | 回读值保持旧值或默认值 | 写入未生效 |

排查时应从底层向上层检查：先确认 I²C 通信正常，再检查 PMBus 状态寄存器，最后验证配置值是否生效。

## 15.7 Datasheet 一致性问题

在 PMBus 集成过程中，如果发现设备 Datasheet 中存在不一致的描述，可按以下思路排查：

1. **命令传输类型与数据字节数矛盾**：例如 Datasheet 标注某命令为 "Read byte" 但数据字节数为 2。这种情况下应以命令的详细描述为准，必要时联系厂商确认。

2. **STATUS 寄存器位域命名不一致**：Datasheet 的不同章节可能使用不同的命名风格（完整描述 vs. 缩写）。以 PMBus 规范的位域定义为准（详见第 8 章和附录 D）。

3. **命令名称不一致**：快速参考表和详细描述中的命令名称可能不同（如缩写差异）。以 PMBus 规范 Table 29 中的标准命令名称为准。

4. **单位表示不一致**：Datasheet 中可能出现 "V" / "Volts" / "v" 混用。在驱动实现中统一使用 SI 标准单位。

> **提示**: 如果 Datasheet 描述与 PMBus 规范存在冲突，优先参考 PMBus 规范，并联系厂商报告不一致之处。
