# 第 5 章 数据格式

> 本章系统讲解 Omnion Power PMBus 模块使用的数据格式，包括数值型格式（VOUT Linear、11-bit Linear）和非数值型格式（位域、Block）。数据格式是解析 PMBus 总线数据的基础——主机从总线上读到的原始字节必须经过正确的格式解码才能得到有意义的物理量。第 2 章已介绍字节和位的传输顺序（低字节先传、LSB first），本章在此基础上讲解 16-bit 数据字内部的编码结构。

---

## 5.1 数值数据格式概述

PMBus 规范定义了多种数值数据格式，用于在固定的 16-bit 数据字段内表达不同动态范围的物理量（电压、电流、温度、功率、时间等）。以下是 Omnion Power 模块支持的数据格式总览：

| 格式 | 数据字结构 | 指数来源 | 典型用途 |
|------|-----------|---------|---------|
| ULINEAR16（VOUT Linear） | 16-bit 无符号尾数 | VOUT_MODE 命令指定 | 输出电压相关命令 |
| 11-bit Linear | 高 5-bit 指数 + 低 11-bit 尾数 | 数据字内部携带 | 遥测读取、保护阈值、时序配置 |

Omnion Power 模块**仅支持 Linear 格式**，不支持 Direct 格式和 VID 格式。

> **关于 Direct 格式**: PMBus 规范中的 Direct 格式使用 Y = (m × X + b) × 10^R 公式进行数值转换，系数 m、b、R 由厂商在 Datasheet 中提供。Omnion Power 模块不实现此格式，主机无需处理 Direct 系数。如需了解 Direct 格式的详细说明，参见 PMBus Specification Part II, Section 7.3。

### 数据格式与命令的对应关系

不同类型的 PMBus 命令使用不同的数据格式。下表展示了完整的对应关系：

| 数据格式 | 命令示例 | 说明 |
|---------|---------|------|
| ULINEAR16（VOUT Linear） | VOUT_COMMAND、READ_VOUT、VOUT_MARGIN_HIGH/LOW | 输出电压相关 |
| 11-bit Linear | READ_VIN、READ_IOUT、READ_TEMPERATURE_1、VIN_ON、IOUT_OC_FAULT_LIMIT | 非电压数值量 |
| 8-bit 位域 | OPERATION、ON_OFF_CONFIG、STATUS_*、FAULT_RESPONSE | 控制与状态 |
| Block（字符串） | MFR_ID、MFR_MODEL、MFR_SERIAL | 设备标识 |

主机驱动在读取数据前，必须根据命令类型选择正确的解码方式。使用错误的格式解码会导致数值完全错误。

### 16-bit 数据字的字节传输顺序

PMBus/SMBus 总线采用低字节先传（Little-Endian）字节顺序。一个 16-bit 数据字在总线上的传输顺序为：

```
[低字节 D0:D7] → [高字节 D8:D15]
```

## 5.2 VOUT_MODE 与电压数据格式

### VOUT_MODE 命令

`VOUT_MODE (0x20)` 是 1 字节命令，用于定义所有输出电压相关命令的数据格式。它本身不直接设置输出电压，而是告诉主机和设备如何解释后续的 VOUT 数据。

VOUT_MODE 的位结构如下：

```text
bit 7       bits 6:5        bits 4:0
Mode flag   Format mode     Parameter
```

| 位 | 含义 |
|----|------|
| bit 7 | Mode flag：0 = 绝对模式（Absolute mode），1 = 相对模式（Relative mode） |
| bits 6:5 | VOUT 数据格式选择 |
| bits 4:0 | 参数（通常是指数 N） |

`bits 6:5` 的格式选择：

| bits 6:5 | 模式 | bits 4:0 参数 |
|----------|------|---------------|
| 00b | ULINEAR16 | 5-bit 二进制补码指数 N |
| 01b | VID | 5-bit VID code identifier |
| 10b | Direct | 固定 00000b |
| 11b | IEEE half-precision floating point | 固定 00000b |

Omnion Power 模块**仅使用 ULINEAR16 模式**，不支持 VID、Direct 和 IEEE 浮点模式。VOUT_MODE 命令为只读，不可修改。

### Omnion Power 模块的 VOUT_MODE 默认值

| 参数 | 值 | 说明 |
|------|-----|------|
| VOUT_MODE 默认值 | 0x14 | 线性模式，指数 = -12 |
| bit 7 | 0 | 绝对模式 |
| bits 6:5 | 00 | ULINEAR16 |
| bits 4:0 | 10100 | 指数 N = -12 |

> **注意**: bits 4:0 = 10100 表示 5-bit 二进制补码值为 -12，即实际指数 N = -12。这意味着 VOUT 数据字的每个最低有效位（LSB）代表 2^(-12) = 0.244 mV。

### ULINEAR16 电压格式

在 ULINEAR16 模式下，输出电压的计算公式为：

```text
VOUT = Y × 2^(N)
```

其中：
- **Y** = 16-bit 无符号尾数（Mantissa），即从 PMBus 读到的原始数据字
- **N** = VOUT_MODE 中 bits 4:0 指定的指数（二进制补码）

对于 Omnion Power 模块，N = -12，因此：

```text
VOUT = Y × 2^(-12) = Y / 4096
分辨率 = 2^(-12) = 0.000244 V ≈ 0.244 mV
```

数据字结构（16-bit）：

```text
15                                        0
+------------------------------------------+
|            16-bit 无符号尾数 Y            |
+------------------------------------------+
```

### ULINEAR16 适用命令

以下命令使用 ULINEAR16（VOUT Linear）格式：

| 命令 | 命令码 | 说明 |
|------|--------|------|
| VOUT_COMMAND | 0x21 | 输出电压设定点 |
| VOUT_CAL_OFFSET | 0x23 | 输出电压读数校准偏移 |
| VOUT_MARGIN_HIGH | 0x25 | 高裕量电压 |
| VOUT_MARGIN_LOW | 0x26 | 低裕量电压 |
| VOUT_OV_FAULT_LIMIT | 0x40 | 输出过压故障限制 |
| POWER_GOOD_ON | 0x5E | PGOOD 断言阈值 |
| POWER_GOOD_OFF | 0x5F | PGOOD 取消断言阈值 |
| READ_VOUT | 0x8B | 输出电压读取 |

### 编码/解码示例（N = -12）

**编码（物理电压 → 数据字）**：

将物理电压值转换为 16-bit 数据字：

```text
目标电压 = 12.000 V
数据字 Y = 12.000 × 2^(12) = 12.000 × 4096 = 49,152 = 0xC000

目标电压 = 11.400 V
数据字 Y = 11.400 × 4096 = 46,694.4 ≈ 46,694 = 0xB666
（取整后精度损失 ≈ 0.0001 V，可忽略）
```

**解码（数据字 → 物理电压）**：

从 PMBus 读到的原始数据字转换为物理电压：

```text
读得数据字 = 0xC000 = 49,152
VOUT = 49,152 × 2^(-12) = 49,152 / 4096 = 12.000 V

读得数据字 = 0xB666 = 46,694
VOUT = 46,694 / 4096 = 11.400 V
```

**VOUT_COMMAND 默认值验证**：

```text
VOUT_COMMAND 默认值 = 12.000 V
对应数据字 = 0xC000
验证: 0xC000 = 49152, 49152 / 4096 = 12.000 V ✓
```

### VOUT 读数范围

| 参数 | 值 | 单位 |
|------|-----|------|
| 读数范围 | 0 ~ 15.9997 | V |
| 分辨率 | 0.244 | mV |
| 最大数据字 | 0xFFFF = 65,535 → 65,535 / 4096 = 15.9998 V | — |

> **提示**: 主机驱动应在启动时读取一次 VOUT_MODE 以获取指数 N，后续所有 VOUT 相关命令的解码均使用该指数。完整的 Python 编码/解码函数参见第 16 章。

## 5.3 11-bit Linear 格式（通用参数格式）

11-bit Linear 是 PMBus 最常用、也最需要理解透彻的数值数据格式。它用于非输出电压类数值命令，包括遥测读取、保护阈值、输入电压配置、时序参数等。

### 格式结构

11-bit Linear 将一个 16-bit 数据字分为两部分：

```text
15        11 10        0
+-----------+-----------+
| exponent  | mantissa  |
+-----------+-----------+
    5 bit       11 bit
```

| 字段 | 位数 | 类型 | 范围 |
|------|------|------|------|
| exponent（指数 N） | 5-bit | 有符号二进制补码 | -16 ~ +15 |
| mantissa（尾数 Y） | 11-bit | 有符号二进制补码 | -1024 ~ +1023 |

数值计算公式：

```text
Value = Y × 2^(N)
```

其中：
- **Y** = mantissa（尾数），11-bit 有符号值
- **N** = exponent（指数），5-bit 有符号值

### 指数 N 的解码（5-bit 二进制补码）

5-bit 二进制补码的编码范围：

| 二进制值 | 十进制值 |
|---------|---------|
| 00000 | 0 |
| 00001 | +1 |
| ... | ... |
| 01111 | +15 |
| 10000 | -16 |
| 10001 | -15 |
| ... | ... |
| 11111 | -1 |

> **提示**: 5-bit 二进制补码的最高有效位（bit 15）为符号位。值为 1 表示负数，需要取反加 1 得到绝对值。

### 尾数 Y 的解码（11-bit 二进制补码）

11-bit 二进制补码的编码范围：

| 二进制值 | 十进制值 |
|---------|---------|
| 00000000000 | 0 |
| 00000000001 | +1 |
| ... | ... |
| 01111111111 | +1023 |
| 10000000000 | -1024 |
| 10000000001 | -1023 |
| ... | ... |
| 11111111111 | -1 |

| 遥测读取 | READ_IOUT | 0x8C |

### Omnion Power 模块的固定指数

Omnion Power 模块对上述命令使用固定的指数值，数据字的指数固定为命令的合理值，不支持更改：

| 固定指数 N | 分辨率 | 适用命令 |
|-----------|--------|---------|
| -3 | 0.125 | READ_VIN、READ_IOUT、READ_TEMPERATURE_1、VIN_ON、VIN_OFF、IOUT_OC_FAULT_LIMIT、IOUT_OC_WARN_LIMIT、OT_FAULT_LIMIT、OT_WARN_LIMIT、VIN_OV_FAULT_LIMIT |

> **提示**: 虽然规范允许 11-bit Linear 的指数在 -16 到 +15 之间自由选择，但 Omnion Power 模块在实际实现中为大多数命令固定了指数值。主机解码时可以直接使用上述固定指数。然而，出于兼容性考虑，建议驱动始终从数据字中提取指数进行解码，而不是硬编码指数值。

### 完整编码/解码示例

#### 示例 1：编码 VIN_ON = 37.0 V（指数 N = -3）

**步骤 1 — 确定指数**：Omnion Power 模块对 VIN_ON 使用固定指数 N = -3。

**步骤 2 — 将 5-bit 指数编码为二进制补码**：

```text
N = -3
二进制补码: -3 = ~2 + 1 = ~00010 + 1 = 11101
E4:E0 = 11101
```

**步骤 3 — 计算尾数**：

```text
Y = Value / 2^(N) = 37.0 / 2^(-3) = 37.0 × 8 = 296
296 的 11-bit 二进制: 00100101000
```

**步骤 4 — 组装 16-bit 数据字**：

```text
数据字 = [11101][00100101000]
        高字节:  11101_001 = 0xE4
        低字节:  00101000   = 0x48

数据字 = 0xE448
```

**验证**：

```text
0xE448 = 1110 0100 0100 1000
指数 = 11101 = -3
尾数 = 00100101000 = 296
Value = 296 × 2^(-3) = 296 / 8 = 37.0 V ✓
```

```text
E4:E0 = 数据字[15:11] = 11101 = -3
```

```text
N10:N0 = 数据字[10:0] = 00100101000 = 296
```

**步骤 4 — 计算物理值**：

```text
VIN = 296 × 2^(-3) = 296 / 8 = 37.0 V
```

#### 示例 3：编码温度值 85.5°C（指数 N = -3）

**步骤 1 — 计算尾数**：

```text
Y = 85.5 / 2^(-3) = 85.5 × 8 = 684
684 的 11-bit 二进制: 01010101100
```

**步骤 2 — 组装数据字**：

```text
指数 N = -3 → 11101
数据字 = [11101][01010101100]
        高字节: 11101_010 = 0xEA
        低字节: 10101100   = 0xAC

数据字 = 0xEAAC
```

**验证**：

```text
尾数 = 01010101100 = 684
Value = 684 × 2^(-3) = 684 / 8 = 85.5°C ✓
```

#### 示例 4：负数编码 — 温度 -10.0°C（指数 N = -3）

**步骤 1 — 计算尾数**：

```text
Y = -10.0 × 8 = -80
-80 的 11-bit 二进制补码:
  80 = 00010100000
  取反: 11101011111
  加1: 11101100000
```

**步骤 2 — 组装数据字**：

```text
指数 N = -3 → 11101
数据字 = [11101][11101100000]
        高字节: 11101_111 = 0xEF
        低字节: 01100000   = 0x60

数据字 = 0xEF60
```

**验证**：

```text
尾数 = 11101100000
符号位为 1，负数:
  取反: 00010011111
  加1:  00010100000 = 80
  所以尾数 = -80
Value = -80 × 2^(-3) = -80 / 8 = -10.0°C ✓
```

#### 示例 5：编码大电流值 210 A（IOUT_OC_FAULT_LIMIT）

210 A 超过了 N = -3 时 11-bit 尾数能表示的最大正值（1023 × 0.125 = 127.875），需要使用更高的指数。

**尝试 N = -1**：

```text
Y = 210 / 2^(-1) = 210 × 2 = 420
420 的 11-bit 二进制: 00110100100（在 -1024 ~ +1023 范围内 ✓）

指数 N = -1 → 11111
数据字 = [11111][00110100100]
        高字节: 11111_001 = 0xF9
        低字节: 10100100   = 0xA4

数据字 = 0xF9A4
```

**验证**：

```text
尾数 = 00110100100 = 420
Value = 420 × 2^(-1) = 420 / 2 = 210.0 A ✓
```

> **提示**: 此示例说明 11-bit Linear 格式的指数可以根据需要调整。当尾数超出 11-bit 表示范围时，增大指数可以降低尾数的绝对值，使其回到有效范围内。编码时选择"使尾数精度最高且不溢出"的最小指数即可。

### 多重编码现象

11-bit Linear 格式存在一个重要特性：**同一个物理值可以有多种合法的编码**。这是因为指数和尾数可以同时调整，只要乘积不变。

例如，值 4.0 V 可以编码为：

| 指数 N | 尾数 Y | 数据字 | 验证 |
|--------|--------|--------|------|
| -3 | 32 | 0xE820 | 32 × 0.125 = 4.0 ✓ |
| -2 | 16 | 0xEE10 | 16 × 0.25 = 4.0 ✓ |
| -1 | 8 | 0xF708 | 8 × 0.5 = 4.0 ✓ |
| 0 | 4 | 0xFC04 | 4 × 1 = 4.0 ✓ |

这些编码全部合法，解码结果完全相同。

> **工程意义**: 多重编码意味着主机在**比较两个数据字是否相等**时，不能直接比较原始数据字，而应先解码为物理值再进行比较。同理，主机在**写入命令时**，应使用与设备相同的指数编码，以确保设备的范围检查逻辑正常工作。建议遵循设备 Datasheet 中给出的指数约定。
>
> Python 编码/解码函数参见第 16 章。

### 特殊值处理

| 条件 | 说明 |
|------|------|
| 尾数 = 0 | 无论指数为何值，结果均为 0（零的编码不唯一） |
| 指数 = 0, 尾数 = 0 | 数据字 = 0x0000，表示"零值" |
| 负电压/电流 | 尾数使用负值表示；Omnion Power 模块的 READ_IOUT 不支持负电流（吸收电流时读数为 0） |
| 数值溢出 | 若物理值超出当前指数下 11-bit 尾数能表示的范围（|Y| > 1023），需要增大指数 |

### Omnion Power 遥测命令的实际分辨率

| 命令 | 固定指数 N | 理论分辨率 | 模块实际分辨率 | 说明 |
|------|-----------|-----------|-------------|------|
| READ_VIN | -3 | 0.125 V = 125 mV | 125 mV | 一致 |
| READ_IOUT | -3 | 0.125 A = 125 mA | 146 mA | 模块实际分辨率受 ADC 精度限制 |
| READ_TEMPERATURE_1 | -3 | 0.125 °C | 0.25 °C | 模块实际分辨率受传感器限制 |

> **注意**: 数据格式的理论分辨率与模块的实际测量分辨率可能不同。实际分辨率受 ADC 位数、传感器精度、校准因子等因素影响，以产品 Datasheet 为准。

## 5.4 非数值型数据格式

除了数值型格式外，PMBus 还使用非数值型数据格式来表达控制命令、状态信息和字符串数据。

### 8-bit 位域格式

位域格式（Bit Field）中，单字节的每一位具有独立的功能含义。主机通过读写特定位来控制设备行为或查询状态。

Omnion Power 模块使用位域格式的命令包括：

| 类别 | 命令 | 命令码 | 说明 |
|------|------|--------|------|
| 系统控制 | OPERATION | 0x01 | 模块开关与裕量控制 |
| 系统控制 | ON_OFF_CONFIG | 0x02 | ON/OFF 引脚行为配置 |
| 系统控制 | WRITE_PROTECT | 0x10 | 写保护控制 |
| 系统控制 | CAPABILITY | 0x19 | 设备能力标志 |
| 故障响应 | VOUT_OV_FAULT_RESPONSE | 0x41 | 输出过压故障响应配置 |
| 故障响应 | IOUT_OC_FAULT_RESPONSE | 0x47 | 输出过流故障响应配置 |
| 故障响应 | OT_FAULT_RESPONSE | 0x50 | 过温故障响应配置 |
| 电源正常 | MFR_PGOOD_POLARITY | 0xE2 | PGOOD 信号极性 |
| 状态寄存器 | STATUS_VOUT | 0x7A | 输出电压状态 |
| 状态寄存器 | STATUS_IOUT | 0x7B | 输出电流状态 |
| 状态寄存器 | STATUS_INPUT | 0x7C | 输入电压状态 |
| 状态寄存器 | STATUS_TEMPERATURE | 0x7D | 温度状态 |
| 状态寄存器 | STATUS_CML | 0x7E | 通信/存储器逻辑状态 |

#### ON_OFF_CONFIG 位域简述

`ON_OFF_CONFIG (0x02)` 是 1 字节命令，配置设备如何响应输入电源、OPERATION 命令以及 ON/OFF 硬件引脚。

| 位 | 名称 | 说明 |
|----|------|------|
| 7 | — | 保留 |
| 6:4 | DEFAULT/OPERATION/CONTROL | 上电行为与控制源选择 |
| 1 | POLARITY | ON/OFF 引脚极性（0=低电平有效，1=高电平有效） |
| 0 | ACTION | 关断方式（0=延时关断，1=立即关断） |

> **提示**: ON_OFF_CONFIG 的详细配置说明参见第 9 章。

#### FAULT_RESPONSE 位域简述

故障响应命令（如 VOUT_OV_FAULT_RESPONSE、IOUT_OC_FAULT_RESPONSE、OT_FAULT_RESPONSE）使用统一的 8-bit 位域格式：

| 位 | 名称 | 说明 |
|----|------|------|
| 7:6 | Response[1:0] | 故障响应类型（关断/立即关断等） |
| 5:3 | Retry[2:0] | 重试设置（不重启/连续重启等） |
| 2:0 | Delay[2:0] | 延迟时间设置 |

> **提示**: FAULT_RESPONSE 的详细位域定义和配置选项参见第 8 章及附录 E。Warning 与 Fault 的区别在于：Warning 表示参数接近限制但设备继续运行，Fault 表示参数越过保护阈值，设备可能触发关断、重试或锁存。

#### STATUS 寄存器位域简述

Omnion Power 模块提供 6 个状态寄存器用于故障和警告监测。STATUS_WORD (0x79) 是最重要的入口——它返回 2 字节的摘要信息，主机一旦检测到非零值，再查询具体的状态寄存器以确定故障/警告的详细类型。

| 状态寄存器 | 命令码 | 数据长度 | 说明 |
|-----------|--------|---------|------|
| STATUS_WORD | 0x79 | 2 字节 | 故障/警告总摘要 |
| STATUS_VOUT | 0x7A | 1 字节 | 输出电压状态 |
| STATUS_IOUT | 0x7B | 1 字节 | 输出电流状态 |
| STATUS_INPUT | 0x7C | 1 字节 | 输入电压状态 |
| STATUS_TEMPERATURE | 0x7D | 1 字节 | 温度状态 |
| STATUS_CML | 0x7E | 1 字节 | 通信/存储器逻辑状态 |

> **提示**: 各 STATUS 寄存器的完整位域定义参见第 8 章及附录 D。故障清除流程参见第 8 章。

#### 位域操作注意事项

> **编程提示**: 修改位域寄存器时，建议先读取当前值，仅修改目标位，再写回完整字节，避免意外改变其他位的状态。主机驱动应使用读-改-写（Read-Modify-Write）模式操作位域寄存器。

### Block 格式（字符串）

Block 格式用于传输可变长度的数据，第 1 个字节为数据长度 N，后续 N 个字节为有效数据。

```text
[长度 N] [数据 1] [数据 2] ... [数据 N]
```

Omnion Power 模块使用 Block 格式的命令：

| 命令 | 命令码 | 用途 |
|------|--------|------|
| MFR_ID | 0x99 | 制造商 ID（"OMPW"） |
| MFR_MODEL | 0x9A | 产品型号 |
| MFR_REVISION | 0x9B | 硬件修订版本 |
| MFR_LOCATION | 0x9C | 制造地点 |
| MFR_DATE | 0x9D | 制造日期 |
| MFR_SERIAL | 0x9E | 产品序列号 |
| MFR_MODULE_DATE_LOC_SN | 0xF0 | 日期/地点/序列号（12 字节，可读写） |

Block 格式传输使用 Read Block 或 R/W Block 传输类型，详见第 4 章。

## 本章小结

本章介绍了 Omnion Power PMBus 模块使用的全部数据格式：

| 格式 | 用途 | 核心公式 |
|------|------|---------|
| ULINEAR16 | 输出电压相关命令 | VOUT = Y × 2^(N)，N 由 VOUT_MODE 指定 |
| 11-bit Linear | 遥测、保护阈值、配置参数 | Value = Y × 2^(N)，N 携带在数据字中 |
| 8-bit 位域 | 控制、状态、故障响应 | 每位独立含义 |
| Block | 字符串型标识信息 | 长度字节 + 数据字节 |

主机驱动必须根据命令类型选择正确的解码方式。**所有编码/解码的 Python 实现参见第 16 章**。PEC 校验确保数据传输完整性，详见第 6 章。
